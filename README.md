# agentic-investment-harness

> 把投资纪律做成文件系统：人类保留最终权威，AI 只做研究与反证。
>
> Discipline lives in files, not willpower — the AI researches and counter-argues, and never trades.

---

## 先说结论

这是一个跑在我 Obsidian 仓库里的个人投资操作系统：投资宪法、交易规则、当前判断、案例库全是文件，AI agent 进来按固定顺序加载、按规则干活。它不预测、不荐股、不自动交易——AI 没有交易授权，写正式文件前还要过独立审查和机械校验两道门。

它做到的是：持仓一到两个月不看盘，到期扫描替我盯；每个决策都能回溯到当时的证据；亏损后的冲动加仓被 24 小时时间锁挡在门外；196 项校验测试全绿；模型在换，这套没换。

如果你也有主业、有点积蓄、自己管自己的钱，往下读。前半部分讲为什么造它，后半部分讲怎么跑起来、怎么换成你自己的。

---

## 一、情景：绕不开的投资理财

我有主业，收入过得去，攒下一点积蓄。钱放活期，购买力一年年缩水；全花掉，又不甘心。所以和大多数人一样，迟早要面对投资理财：股票、基金、加密资产，总得碰一两样。

这件事绕不开，也没有谁能替你完成。别人可以给你建议，但钱是你的，亏损也是你的。这种事没有截止日期，于是永远可以拖——直到某次大跌替你做了决定。

---

## 二、冲突：两个绕不开的难

### 难题一：想跑赢通胀，又怕亏本金

我被夹在中间。这两件事天生打架——高收益的资产必然波动大，想要本金安全就得接受低收益。

没有系统能同时给你"高收益 + 零风险"，所有声称能的都是骗子。这个矛盾消灭不了，只能管理：先想清楚赚哪类钱，再把每一次错的代价压到可承受。

### 难题二：短期波动会吃掉理性

这是核心的难，先交代我自己的真实状态：每天刷行情，涨了想知道为什么涨，跌了想知道要不要跑。注意力被持仓绑架，主业成了后台程序。跌了想补仓，涨了怕踏空，亏了想翻本——每次都觉得"就这一次，不一样"。

我不是特例。行为金融学几十年前就把这件事量化了：

| 发现 | 数据 | 出处 |
|---|---|---|
| 看盘越勤，越拿不住 | 高频查看结果的一组，股票配置约 41%；低频组约 70% | Thaler、Tversky、Kahneman 与 Schwartz（1997） |
| 赚小钱就跑，亏大钱死扛 | 一万个美国券商账户里，卖出盈利股的概率 14.8%，约为卖出亏损股（9.8%）的 1.5 倍 | Odean（1998） |
| 日内交易基本是绞肉机 | 坚持日内交易超过 300 天的人里，97% 亏损 | Chague et al.（2020，巴西数据） |
| 买入常常不是研究驱动 | 个人投资者系统性净买入放量、上新闻、当日大涨的"注意力股"，这类买入随后表现偏弱 | Barber & Odean（2008） |

这张表的意思：散户亏钱多数输在行为而非智商——波动一来，人的本能反应就在系统性地漏钱。台湾的数据更直接：散户因过度交易每年落后约 3.8 个百分点（Barber/Lee/Liu/Odean，2009）。

**我最大的敌人不是市场，是自己在波动中的反应。**

那把问题重新说一遍。"预测得更准"靠不住；"靠意志力自律"也靠不住——意志力恰恰在最需要它的时刻最不可用。剩下的问题只有一个：能不能把"冷静时的我"固化成规则，让"波动的我"只能在这个框架里行动，把信息处理的苦力活外包给 AI？

## 三、答案：把投资做成一个系统

我的答案分三件事：先想清楚赚什么钱，再想清楚 AI 能干什么，最后才是造系统。

### 第一件事：先想清楚赚什么钱

多数人一进场就问"买什么"，这是错问题。先问赚什么钱。普通人能赚的钱分三类，载体和要盯的东西完全不同：

| 钱的类型 | 例子 | 载体 | 真正要盯什么 |
|---|---|---|---|
| 宏观流动性（水池水位变化） | 全球放水/收水，稀缺资产重估 | 黄金、比特币 | 水位（流动性与稀缺性共识），不是某家公司基本面 |
| 行业 beta（行业趋势） | 行业景气上行 | 行业 ETF | 景气度与拥挤度 |
| 个股 alpha（公司超预期） | 经营持续超市场认知 | 个股 | 经营证据：订单、利润、现金流 |

白话讲：拿着水池的逻辑买个股，或者用个股的逻辑拿 ETF，都是框架错配——钱亏了都不知道该怪哪一层。所以系统里每个投资判断必须先声明赚的是哪一类钱，再谈值不值。

周期也要先声明：短期（半年内要见到结果）和长期（一到两年）是两套耐心。同一个回调，对长期持仓是噪声，对半年内要用的钱是实打实的风险。

### 第二件事：承认 AI 的强项和弱项，重新分工

想用 AI 的冲动是真的：AI 一分钟能生成一百篇"深度报告"，没人看得完；我自己收藏的报告越攒越多，后来也说不清哪份还在指导当前决策。所以问题不是要不要用 AI，是怎么分工。

AI 强在信息处理：读得快、不知疲倦、没有面子问题。弱在替我做决定：它不知道我的总资本、风险承受力和睡眠质量。更弱在替我保持纪律——因为它太好说话。

最后这条是用失败换来的。我最开始试的办法最直觉：让一个理性的 AI 陪我聊，在我冲动的时候劝住我。失败。不是我意志不坚定，是它意志不坚定——它太顺着我说，聊到最后总是它同意我。缠着 AI 直到它点头，比说服自己容易多了。

所以这个系统里有一条看起来很怪的规则：AI 之间的一致意见不算独立证据——它们太容易一起点头。这条规则就是那次弯路换来的。

另一条设计品味：给"不做"留一个合法的位置。AI 拒绝一个动作时，一行"不做，因为 X"就够了，不需要三段免责声明。免责声明是模型的自我保护，不是给我的信息。

### 第三件事：造一套 harness，把纪律做进结构

打台球的人都知道架杆（rest）：球位够不着、手会发抖的时候，用一根杆架住球杆。架杆不提高你的准度，它让你的手在那个球位上保持稳定。

Harness（直译"马具"）就是 AI 的架杆：模型权重之外的一切工程设施——指令、工具、环境、状态、反馈，五个子系统。同一个模型，裸跑和配上完整 harness，可靠性的差距远大于换一个更贵的模型。**Harness 不让 AI 更聪明，它让聪明变得可靠。**

这套 harness 具体做了三件事：

1. **把投资理念写进系统。** 改变 AI 在这个仓库里的"调性"：先加载"我"，再加载通用知识。我的投资宪法、决策规则、踩过的坑做成知识层，按需加载。模型的默认倾向来自训练，通用且中位；你喂给它什么判断标准，它就输出什么形状的判断。这不是玄学，是上下文工程——系统不改模型权重，也改不了。

2. **把调研方法做成流程。** 选标的的路径固定：声明赚哪类钱 → 路由到对应证据要求 → 候选池 → 负向筛选 → 深度研究 → 四票评估 → 六档动作。负向筛选是攒出来的资产：每个失败案例沉淀进错误库，下次同类标的自动命中排除。这种活要记性好、耐得住重复，还绝不嘴硬——AI 干得比我强。

3. **把纪律做进结构。**
   - 四票分立：经营（H_B）、赔率（H_R）、周期（H_L）、仓位（H_C）分开投票，价格下跌只能改善赔率票，不能提高经营票；
   - 时间锁：亏损后想加仓、抄底，默认冻结新增风险 24 小时——睡一觉再决定；
   - maker-checker：干活的 AI 和只读的审查 AI 分开，写入前再跑机械校验脚本，校验失败一律挡住；
   - 判断会腐烂：每个判断带数据截止日和过期日，旧判断不自动授权今天的行为。

一句话：**我不依赖 AI 的理性，我靠结构让情绪进不了决策路径。**

### 架构速览（面向工程师）

最小加载链——不全量加载，按任务只读命中的路径：

```
AGENTS.md → PATHS.md → CONTENT_ROUTER.md → 命中的道/Skill → Current State → Evidence
```

四票表：

| 票 | 判断什么 | 只靠什么更新 |
|---|---|---|
| H_B 经营胜率 | 这家公司/资产能不能持续赚钱 | 经营证据：订单、利润、现金 |
| H_R 赔率 | 当前价格值不值 | 价格 vs 价值差距 |
| H_L 周期 | 现在是什么市场阶段 | 软探测器，只影响进入时点 |
| H_C 仓位 | 该投多少 | 总资本分母和风险预算 |

这张表的用法：三张硬门票（经营/赔率/仓位）任一失败或未知，默认不增加风险；动作只有六档——`不投入 / 继续观察 / 建立验证仓 / 升级确认仓 / 不加仓 / 降级或退出`，没有第七种表达。

双重检查的第一道是 Reviewer——工具权限硬限制为只读的审查 agent：`PASS` 放行、`BLOCK` 退回、`DISAGREE` 保留双方判断不折中，主 agent 只能增加审查不能取消。

第二道是 Validator——写入前的机械校验脚本：路径白名单、时间自洽、来源完整，fail-closed。

状态带过期——`03_STATE/` 里每个 thesis 带 `data_cutoff` 与 `expires_at`，到期扫描替代盯盘。系统不汇报"我知道了什么"，只提醒"哪个判断该重新验证了"。

加载顺序同时是成本设计：稳定的文件（宪法、合同）放在前部不轻易改，prompt cache 命中后又快又省；易变状态放后面。能用脚本校验的检查绝不花 token——Validator 免费，Reviewer 花钱。

五个子系统在本仓库的落点：指令（`AGENTS.md` 与 `01_道/`）、工具（文件系统与校验脚本）、环境（仓库本身）、状态（`03_STATE/`）、反馈（Reviewer、Validator、错误库）。

## 四、结果：拿到了什么，没拿到什么

先说拿到手的，再交代没拿到的。

- 持仓期间一到两个月基本不看盘，到期扫描替我盯：什么过期了、什么该复查、什么被新证据证伪；
- 196 项机械校验测试全绿，CI 每次提交都跑，写入校验没被绕过；
- 每个决策全链路可回溯：当时依据什么证据、哪个证据后来被证伪、案例进了错误库还是案例库；
- 踩过的坑变成错误库资产，同类标的自动排除，越用越准；
- 模型无关——这套系统跑过不止一代模型，结构没跟着换。

没拿到的，一样列清楚：

| 痛点 | 能解 | 不能解 |
|---|---|---|
| 情绪化决策 | 冷静期 + 强制反方证据，冲动先过流程 | 消除情绪本身；你仍然可以绕过它 |
| 盯盘时间 | 到期扫描 + 事件触发，降低看的必要性 | 消除"想看"的冲动 |
| 信息过载 | 来源分层、同根信息只计一次、只萃取增量 | 创造新信息；保证预测正确 |
| 收益差距 | 收窄行为差距（少亏在自己手上） | 承诺收益；创造 alpha |

换句话说：它不承诺收益，不创造 alpha，不消除情绪本身，你随时可以绕过它。它只是让"按规则办事"比"凭感觉办事"更省力。

**投资的正确状态是无聊。** 这套系统在后台稳定运转，我的注意力留给主业和生活。它挡不住更强的模型出现，但模型越强，越需要一套结构来决定这份强往哪使。

## 实用区

以上是为什么造它。以下是它长什么样、怎么跑、怎么变成你的。

### 实际使用起来什么样

以我的持仓节奏（一到两个月一轮）为参照：

- 新材料丢进来，先得到"有没有增量、值不值得细读"的判断，不再全文精读；
- AI 生成一百篇报告不再堆积成山——同根信息只计一次，进入体系的只有萃取版；
- 想加仓的念头不再直接变成动作，它先变成一次四票评估；
- 复盘不再是回忆，是翻记录：证据、审查、结算都留了痕。

### 项目不做什么

- 不荐股——没有选股信号、目标价、仓位建议；
- 不保证收益——没有"确定涨"的判断；
- 不自动交易——AI 没有交易授权、仓位修改权、自动成交权；
- 公开的 `03_STATE/` 是作者个人状态记录，不是任何人的买卖建议。

这四条不是谦虚，是设计：AI 的角色被故意限制在研究与反证，权限分层是特性，不是不成熟。

### 目录地图

```
00_HOME/           路径索引、任务分流
01_道/             投资宪法（Guardrail）、认知前台
02_术/             交易系统（四票、六档动作）、技能
03_STATE/          当前 thesis、预期、领域模型（带过期时间）
04_CASE_GYM/       案例、错误库、交易日志
05_EVIDENCE_META/  来源、知识、证据层
90_AUTOMATION/     验证器、审查协议、测试
归档/              旧分析报告（兼容引用）
```

这套目录首先是给 AI 读的地图，每个目录在 `AGENTS.md` 里都有明确的加载时机；人看得懂，纯属顺便。

### 五分钟跑测试

```bash
git clone https://github.com/bor799/agentic-investment-harness.git
cd agentic-investment-harness

# Validator 测试（196 项）
python3 -m unittest discover -s 90_AUTOMATION/TESTS -p 'test_*.py'

# 发布安全审计
python3 90_AUTOMATION/PIPELINES/audit_publication.py .
```

全绿 = 写入校验和发布安全检查没有被绕过。跑通这两条，你看到的和我每天看到的一样。

如果只想看看一个判断长什么样，直接翻 `03_STATE/` 下任意一份 thesis 卡。

### 怎么换成你自己的

1. 保留 `90_AUTOMATION/`——验证器和测试是通用骨架；
2. 替换 `01_道/`——写你自己的宪法、认知、风险纪律；
3. 改 `02_术/TRADING_SYSTEM/PARAMETERS.md`——设你自己的总资本和风险预算；
4. 清空 `03_STATE/` 和 `05_EVIDENCE_META/`——从你自己的研究开始积累；
5. 读懂 `AGENTS.md` 再改——它定义 agent 的行为边界。

提醒一句：骨架五分钟能 fork 走，但价值的大头在你的宪法和错误库，那要用你自己的钱和教训慢慢填。

### 自进化如何发生

```
Evidence / Case
    ↓
Method Proposal（对话中形成，不直接落盘）
    ↓
独立 Reviewer
    ↓
CI / Validator
    ↓
人类合并
```

AI 只能提方案，不能直接改宪法和交易系统正文。每次方法变化走同一条路：提案 → 反方审查 → 机械校验 → 人类合并。所以这套系统会变，但每一次变化都有记录、有审查、有人类的合并动作。

### 参考与致敬

- 处置效应、注意力买入、过度交易的实证来自 Odean、Barber 及其合作者的系列论文，数字见上文表格；
- maker-checker 是银行业用了几十年的双人原则，我只是把它搬进了个人投资；
- harness 五子系统（指令、工具、环境、状态、反馈）的拆法来自 agent 工程社区的通行说法；
- 高频查看压低风险资产配置的现象叫"近视性损失厌恶"（myopic loss aversion），就是上文那组 41% vs 70%；
- 至于判断带过期时间、AI 一致意见不算证据这两条，任何框架里都找不到出处——出处是我自己踩的坑，清单在 `04_CASE_GYM/`。

### 贡献

AI agent 的贡献走固定流程：

1. 在 `agent/*` 分支上工作；
2. 创建 draft PR；
3. PR 必须通过 CI + Validator + 发布审计；
4. `main` 禁止强推和删除；
5. 只有人类仓库所有者能合并。

"人类合并"是字面意思——AI 可以写 PR，不可以点 merge。详见 `CONTRIBUTING.md`。

### 风险声明

- `03_STATE/` 中的 thesis 和动作表达是作者的个人状态快照，有过期时间，不代表当前判断；
- 任何人不应基于本仓库内容做出投资决策；
- 投资有风险，决策需自行判断并承担后果。
