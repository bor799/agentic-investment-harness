# 03 Feedback Loop

## 日常记录最小要求

日报、公司研究、风险动作和明确不行动都必须记录三件事：今天发生了什么、这件事为什么重要、现在该做什么或不做什么。

任何信息进入系统前，先标记为 `事实 / 推断 / 假设 / 情绪`。事实要有来源、数据时点和口径；推断要写能更新哪张票和不能证明什么；假设没有参考类、期限、结算规则和历史校准时，概率写 `uncalibrated`；情绪只交给行为纠偏，不能修改 `H_B 经营`、仓位或失败条件。

动作只允许六档：`不投入 / 继续观察 / 建立验证仓 / 升级确认仓 / 不加仓 / 降级或退出`。如果输出“看多、重仓、抄底、梭哈”等未授权词，必须改写成六档之一。

## 决策冻结模板

风险增加被讨论、交易完成或明确不做时，在记录中冻结：

```yaml
decision_freeze:
  timestamp:
  thesis_type: 基本面 | 流动性 | 风险偏好 | 认知差 | 事件跳变
  valuation_language:
  H_B:  # 经营
  H_R:  # 赔率
  H_L:  # 周期（软探测器）
  H_C:  # 仓位
  three_numbers_to_verify:
  failure_conditions:
  max_loss:
  broker_fact: confirmed | pending | not_applicable
  allowed_action:
  next_review_clock:
```

成交未确认时，状态写“待券商回报”。研究、挂单未成交和 AI 计算不能伪装成持仓。

## Case 进入系统

Case 记录当时发生了什么、事前判断是什么、实际结果是什么、哪个方法版本参与、什么事实说明方法错了。

## Case 能改变什么

单个 Case 可以生成临时防火墙、研究问题或实验性 Skill 更新。它不能直接生成道或 Constitution 条款。

## Case 进入 Philosophy Inbox 的条件

1. 多个相互独立案例反复出现。
2. 有明确因果机制，不只是结果相似。
3. 已做反例审查。
4. 在不同市场状态下仍有解释力。

满足四项也只获得候选资格，仍不能自动进入 MINDSET。

## 三类反馈

复盘必须分开结果反馈、过程反馈和纪律反馈。赚钱但违规，纪律仍记失败；小损失但流程正确，过程不自动判错。

次日和 3 个交易日复盘只看周期持续性、流动性、折溢价、宽度和事前验证项，不用单日盈亏给体系打分。下一经营事件到来时，检查收入、毛利、经营利润、现金流、库存、供给或公司专属 KPI；媒体重复而数字不变，不能升级经营票（H_B）。

每周随机抽三次“做/不做”，写 `情绪 → 判断 → 动作 → 后果` 因果链，不能只挑成功案例。月度纪律评分 `≤6/10` 时进入 7 天 `research_only`；解除标准需要 Murphy 人工确认，系统不得自动恢复风险增加。

## 卖飞和错误

卖出后价格继续上涨，先对照当时冻结的 thesis、估值、周期和仓位票。若退出符合事前规则，记录为正确流程，不用事后最高价羞辱流程；如果原 thesis 没坏、仅因短期波动退出，才记录为流程问题。

规则被新证据修订时，必须写明旧规则、为什么覆盖、新规则和适用边界。没有版本记录，禁止静默删除旧认知。

## 方法训练日志

方法训练不是给标的打分，而是改进判别式。每轮训练至少记录：

- 训练样本和数据截止日。
- 新增判别式。
- 旧框架被修正的地方。
- 下一轮验证队列。
- 未解决问题。
- 历史版本和回滚条件。

训练日志里的 `通过`、`完成`、覆盖率、自评分和候选标签，只说明方法测试状态。它们不能替代公司证据、估值、周期和资本纪律。
