# BEHAVIOR_REVIEW

## 职责

在情绪强、亏损、踏空、AI 共识、回本愿望出现时先做反方审查。

## 输入

用户语言、持仓状态、浮盈亏、连续涨跌、纪律触发、AI 依赖迹象。

## 输出

最大漏洞、反证、最坏代价、低风险表达和允许动作。

## 不能证明什么

行为触发器不能证明标的变差，也不能替代业务证据。

## 失败条件

用户观点被顺着找理由，或亏损后无新增经营证据却增加风险。

## 九问反方审查

1. 这件事最大的三个漏洞是什么？
2. 什么事实能证明我错？
3. 市场为什么可能是对的？
4. 我忽略了什么信息？
5. 胜率真的提高了吗，还是只是价格跌了？
6. 赔率改善了吗，还是损失上限变大了？
7. 最坏代价是什么，会不会伤害生存？
8. 这笔收益值得这个风险吗？
9. 有没有更低风险表达同一个观点的方式？

任何风险增加候选出现前，九问必须先完成。任一关键问题答不清，动作不得升级。

多个 AI 或媒体同意时，要追溯独立根证据；同根信息重复只计一次，不提高置信度。观点如果需要“别人都错了”才能成立，必须解释对手可能有的赎回、期限、杠杆、监管或套保约束；无法解释市场为什么可能正确，thesis 不完整。

## 状态差检查

| 状态 | 默认动作 |
|---|---|
| 未持仓，怕错过 | 接受错过，继续观察 |
| 持仓浮亏，想回本 | 冻结新增风险，只接受新增经营证据 |
| 持仓浮盈，怕卖飞 | 重做当前价格四票，不用最高价复盘 |
| AI 共识很强 | 检查是否同根信息，不提高独立证据权重 |
| 想卖 Put 降成本 | 先按风险增加和期权最大损失审查 |

触发词包括：已经跌很多、错杀、回本、梭哈、怕错过、别人不懂、市场恐慌、卖 Put 降成本、AI 都同意。出现这些词时，先记录情绪，再做反方审查；审查完成前禁止讨论风险增加。

价格更低只允许改善赔率票（H_R）；如果把价格下降写成经营胜率提高，退回重写。亏损后想加仓、抄底或卖 Put，冻结新增风险至少 24 小时；撤单、平仓、减仓等风险降低动作不被冷静期阻断。

## 交易前和暴跌后流程

准备下单前，用 30 秒回答：

```text
当前情绪是什么？
新增经营事实是什么？
有没有混淆价格、价值、胜率和赔率？
总资本最大损失是多少？
没有 AI 时，我能不能独立说明这笔交易？
```

答不清时，动作缩到 `不投入/继续观察`。

暴跌后产生动作冲动时，按 5 分钟流程执行：

```text
1 分钟不下单，只记情绪
→ 1 分钟只写事实
→ 1 分钟分 H_B 经营 / H_R 赔率 / H_L 周期
→ 1 分钟算单票、集群和 O 预算
→ 1 分钟选择六档动作
```

未完成时，默认 `不加仓`。15 到 30 分钟观察、1.5% 到 2% 回升或类似盘面条件，只能重启研究，不能让四票自动通过。

## 悬置容器

问题重要、信息未齐且无需立即减险时，使用悬置容器：

```yaml
suspended:
  question:
  known_facts:
  missing_evidence:
  next_review_time:
  failure_condition:
  allowed_action: 继续观察 | 不加仓
```

`suspended` 只映射为 `继续观察/不加仓`，不是第七种动作。失败条件、资本超限或退出规则已经触发时，悬置立即结束，不能用等待阻断 `降级或退出`。

## 输出格式

```yaml
behavior_review:
  trigger:
  strongest_opposing_case:
  evidence_that_would_disprove_me:
  market_may_be_right_because:
  worst_loss:
  lower_risk_expression:
  allowed_action:
  cooldown_or_review_time:
```

## 能改什么

行为审查可以临时冻结风险、生成 Case、更新实验性 Skill 或要求复查；不能直接把单次情绪或单次盈亏写进 MINDSET / Constitution。
