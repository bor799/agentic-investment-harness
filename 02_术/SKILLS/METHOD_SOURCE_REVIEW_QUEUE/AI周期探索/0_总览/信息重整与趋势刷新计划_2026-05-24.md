# 信息重整与趋势刷新计划

制定日期：2026-05-24

## 目标

把现有股票投资研究库里的历史公司研究、投资池、Mindspace/MongoDB 信源、新闻媒体、市场趋势和关注标的重新整理成一个可循环更新的情报系统。

核心不是重新写一批分析报告，而是建立一条稳定链路：

```text
本地关注标的/投资池
  -> Mindspace Source MCP / MongoDB 文章
  -> 必要时 agent-reach fallback
  -> 证据日志
  -> 公司级判断更新
  -> 投资池和产业结构情景更新
```

## 当前项目盘点

### 已有核心结构

- `AI周期探索/0_总览/研究对象清单.md`：已有主研究对象清单，覆盖美股、港股、A股、私有公司和工具类标的。
- `AI周期探索/0_总览/company_queue.md`：主公司研究队列，当前全部为 `completed`。
- `AI周期探索/0_总览/new_company_intake_queue.md`：新公司纳入队列，含交易权限字段和 watch trigger。
- `AI周期探索/0_总览/company_score_table.md`：主评分表，包含结构性转变、真瓶颈、定价权、利润率变化、验证信号、三年路径、分类、总分。
- `AI周期探索/0_总览/MINDSPACE_SOURCE_MCP_SOP.md`：Mindspace Source MCP 的强制信源控制 SOP。
- `AI周期探索/0_总览/BOTTLENECK_3X_FRAMEWORK.md`：产业瓶颈和三年三倍反推框架。
- `AI周期探索/04_投资池/`：核心候选、观察、期权、瓶颈观察、证据不足等池。
- `AI周期探索/02_公司研究/{公司}/`：标准公司研究目录，含 `company_research.md`、`scorecard.md`、`evidence_log.md`、`next_questions.md`、`PROMPT.md`。

### 投资编号现状

未发现独立的 `投资编号` 字段。现有稳定标识主要是：

- 公司名
- ticker / 代码
- 市场 / 板块
- 队列状态
- 交易权限
- 分类 / 总分

实施时建议补一个轻量的 canonical id，不改历史文件大结构：

```text
INV-{市场}-{ticker_or_code}
例：
INV-US-MDB
INV-US-NET
INV-CN-300390
INV-HK-09992
```

该 id 只用于索引和跨文件对齐，不替代公司名和 ticker。

## 数据源路由

### 第一层：本地库

先读本地文件，避免重复研究：

1. `company_score_table.md`
2. `new_company_intake_queue.md`
3. `04_投资池/*.md`
4. 目标公司的 `evidence_log.md`
5. 目标公司的 `next_questions.md`

### 第二层：Mindspace Source MCP / MongoDB

所有公司研究刷新都 MCP-first。

每家公司最多选 1-3 个 channel，最多尝试 5 个候选 channel。核心证据必须 `get_article_detail` 回源，不使用搜索摘要直接下结论。

默认搜索窗口：

- 结构性变化：365 天
- 财报 / 经营验证：180 天
- 新闻 / 情绪 / 催化剂：90 天
- 市场趋势面：30-90 天

### 第三层：agent-reach fallback

触发条件：

- MCP 没有财报、估值、竞争、监管、新闻趋势中的关键桶。
- 只有媒体/论坛/播客，没有高质量来源。
- A股、港股、小众行业或中概股 MCP 覆盖明显弱。
- MongoDB 超时或 channel 轮换导致无法回源。

优先来源：

- 美股：StockAnalysis、SEC、公司 IR、Yahoo/Google Finance 作为补充
- 港股：HKEXnews、公司 IR、Google Finance、官方公告
- A股：巨潮资讯、上交所/深交所、东方财富、同花顺、公司公告
- 私有公司：官网、融资文件、可靠媒体、未来 IPO 文件

## 萃取和入库标准

每条进入判断链的证据必须进入 `evidence_log.md`，至少包含：

| 字段 | 说明 |
|---|---|
| source_name | 来源名 |
| source_tab | 来源类型 |
| link | 原文链接 |
| published_at | 发布时间 |
| evidence_use | 支撑的判断 |
| confidence | 高 / 中 / 低 |
| notes | 限制、冲突或剩余缺口 |

长文、研报、深度文章进入 `knowledge-extractor` 萃取逻辑：

- 一句话结论
- 反常识/水下信息
- 关键数据
- 可复用框架
- 风险和不确定性

事实和推断分开写：

- `Evidence`：原始事实
- `Inference`：我的解释
- `Confidence`：置信度
- `Gap`：还缺什么

## 产业结构情景层

每轮刷新不只更新单家公司，还要产出产业流动视角。

建议固定五个层：

1. **AI Agent 控制面**：MSFT、GOOGL、NET、DDOG、CRWD、OKTA、CYBR、FROG
2. **数据与上下文层**：MDB、SNOW、ESTC、PLTR、TEAM、CRM
3. **AI 物理瓶颈层**：NVDA、MU、MRVL、VST、SMR、LITE、AI PCB 组
4. **中国平台与消费品牌**：BABA、Tencent、PDD、Meituan、Xiaomi、Pop Mart、Miniso、Bilibili
5. **周期材料和制造出海**：天华新能、湖南裕能、福耀玻璃、分众传媒、CRRC、Aux Electric

每个层输出：

- 近期新闻密度
- 证据增量
- 市场情绪变化
- 价格/估值敏感区
- 6-12 个月验证信号
- 升级/降级候选

## 实施步骤

### 阶段 1：只读基线

完成项：

- 盘点本地目录。
- 确认 Mindspace MCP bridge 可用。
- 确认 agent-reach 可用渠道和缺口。

下一步：

- 建立 master watchlist。
- 建立 source health 文件。
- 抽取所有 `next_questions.md` 成为 refresh target。

### 阶段 2：公司级证据刷新

对每个 P1 公司执行：

1. 读取本地四件套：`company_research.md`、`scorecard.md`、`evidence_log.md`、`next_questions.md`。
2. MCP `search_channels`。
3. MCP `search_articles`。
4. MCP `get_article_detail`。
5. 不足则 agent-reach fallback。
6. 更新 `evidence_log.md`。
7. 只在证据有实质增量时更新 `company_research.md` 和 `scorecard.md`。
8. 同步 `company_score_table.md` 和 `run_log.md`。

### 阶段 3：主题级趋势刷新

按产业层搜索，不先锁定公司：

1. 最近 30-90 天新闻/媒体/行业报告。
2. 找新增公司或新增瓶颈。
3. 只把有交易路径或强信号的对象进入 `new_company_intake_queue.md`。
4. 输出主题情景文件。

### 阶段 4：投资池重排

更新：

- `核心候选池.md`
- `瓶颈观察池.md`
- `观察池.md`
- `期权池.md`
- `证据不足池.md`
- `暂不研究池.md`

每次移动必须写：

- 触发证据
- 升级/降级原因
- 失败条件
- 下一验证信号

## 完成标准

第一轮实施完成时，至少应有：

- `watchlist_master.md`
- `source_health_2026-05-24.md`
- `refresh_targets_2026-05-24.md`
- 至少 5 家 P1 公司完成证据刷新
- `市场趋势面_2026-05-24.md`
- `产业结构情景_2026-05-24.md`
- `run_log.md` 增加本轮记录

每家公司刷新必须满足：

- 至少 2 条高质量证据，或明确 `evidence_limited_after_fallback`
- 财报/经营、估值、结构变化、失败条件至少覆盖 3 类
- 每个核心判断能追溯到 `evidence_log.md`
- 所有日期使用绝对日期

## 主要风险

- Exa、Twitter、Reddit 当前不可用，会削弱市场情绪和社交趋势覆盖。
- Mindspace channel 会轮换，必须保存 source/item 回源信息，避免只保留会话记忆。
- A股/港股数据容易混用币种和股本口径，必须标清人民币、港币、美元。
- 新闻热度不等于投资价值，必须回到瓶颈控制、利润留存、估值隐含预期。
- 周期材料和 PCB 标的容易被短期价格/订单带偏，必须设置价格和毛利率失败条件。

## 建议启动方式

先执行阶段 1，不直接大规模改公司结论：

```text
建立 watchlist_master + source_health + refresh_targets
```

确认这三个索引无误后，再进入 P1 公司级刷新。
