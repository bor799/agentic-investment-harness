# STRUCTURAL_CHANGE_BOTTLENECK

## 职责

发现新秩序中的必经点和瓶颈。

## 输入

产业变化、技术路线、监管、CapEx、客户预算。

## 输出

必经点、绕开路径、稀缺持续期、供给反噬时钟。

## 不能证明什么

必经不等于好投资，三倍候选不授权交易。

## 失败条件

客户自建、替代、扩产或监管使瓶颈失效。

## 发现流程

1. 先写新秩序是什么，不用宏大叙事替代付款人。
2. 找 1 到 3 年内必须经过的环节。
3. 判断环节是不是稀缺，不是只看热门。
4. 检查谁真正拥有收费权。
5. 检查收入是否能穿透到利润和现金。
6. 启动供给反噬时钟。
7. 只把候选放入研究优先级，不直接给交易动作。

## 挖掘端七步法

结构性机会从宏观叙事进入研究后，要一路向下钻到工程参数、材料、工艺、良率、交付周期和客户认证：

```text
需求端
→ 工程参数
→ 设备结构
→ BOM / 材料 / 工艺
→ 供给瓶颈
→ 控制权
→ 利润和估值
```

1. **需求端：**谁在付钱，需求事件是否变密，预算是否真的释放。
2. **工程参数：**需求变成什么物理指标，例如带宽、功耗、层数、容量、时长、可靠性、交付周期。
3. **设备结构：**哪些设备必须升级，例如交换机、PCB、储能系统、变压器、液冷、UPS。
4. **BOM / 材料 / 工艺：**需要哪些材料和工艺，例如铜、CCL、ABF、T-glass、InP、LFP、电解液。
5. **供给瓶颈：**瓶颈是资源、产能、良率、认证、设备、施工、并网还是运维。
6. **控制权：**谁控制瓶颈，是平台厂、材料厂、设备厂、资源厂还是系统集成商。
7. **利润和估值：**需求能否进入收入、毛利率、现金流，当前价格是否已经透支。

需求真实不等于公司受益。必须证明需求能沿链条传导到这家公司，并且这家公司能留下利润。

## 九步漏斗

完整主题训练使用九步漏斗；七步法是前台精简版。

| 步骤 | 任务 | 进入下一步的标准 |
|---|---|---|
| S1 宏观双扫描 | 产业需求和市场流动性分账 | 能说清需求账户和流动性账户分别更新哪张票 |
| S2 付款人确认 | 找最终付款人、预算、刚性和周期 | 至少 1 个可跟踪预算、订单、渗透率或使用量指标 |
| S3 产业链物理拆解 | 拆上游、中游、下游、服务、渠道、基础设施 | 每一环能映射成本、利润池和候选公司 |
| S4 逆向溯源 | 沿 BOM、材料、工艺往上找卡点 | 定位至少 1 个扩产慢、认证难或 CR3 高的环节 |
| S5 供给评估 | 看 CR3、扩产、认证、资本、利用率、地缘、反噬 | 能给每个环节写强/中/弱和反证 |
| S6 七步瓶颈测试 | Need / Transmission / Constraint / Control / Pricing / Capture / Duration | 不过测试的环节只进信号池或剔除池 |
| S7 定价权排序 | 比较 ASP、毛利率、订单能见度和客户切换成本 | 至少找出一个最可能留住利润的环节 |
| S8 标的映射 | 公司、代码、主营、市占、客户、产能、估值、跟踪指标 | 字段不足时进待补池，不进交易决策 |
| S9 事件日历 | 写 3-12 个月验证事件、输入源完整度和失败条件 | 只给研究优先级和复查时钟，不给自由仓位 |

S9 的输入源必须标清：文章类样本只能产出事件日历；财报、估值、流动性和资本数据齐了，才进入四票和六档动作。

## 七步瓶颈测试

| 测试 | 问题 | 失败信号 |
|---|---|---|
| Need | 客户必须解决这个问题吗 | 只是锦上添花、预算可推迟 |
| Transmission | 需求能传到这个环节和公司吗 | 需求停在下游热度，进不了公司收入 |
| Constraint | 供给是否被时间、资本、技术、监管或认证卡住 | 竞争者可快速复制，客户可自建 |
| Control | 谁控制瓶颈和客户入口 | 公司只是参与者，没有入口、标准、数据、供应或认证 |
| Pricing | 公司能提价或维持价差吗 | 量增价跌、毛利率下行 |
| Capture | 价格和需求能留下利润和现金吗 | 收入增长被成本、费用、营运资本或 CapEx 吃掉 |
| Duration | 稀缺能持续到财务兑现吗 | 扩产、替代或政策强制降价先到 |

每个主题还要补 5-10 条专属失败条件。没有失败条件的产出无效。

## 瓶颈迁移与反简单叙事

新瓶颈出现，不等于旧瓶颈消失。AI 基础设施这类系统里，瓶颈会从 GPU/HBM 迁移到连接、电力、冷却、储能、材料、测试和并网；但不能把它简化成单一口号，例如“光替代铜”或“铜就是唯一瓶颈”。

真正值得挖的是共同瓶颈：无论技术路线怎么切换，都绕不开、扩不快、认证难、利润能留下来的环节。最热概念不一定最先进入财报；更现实的兑现层可能是老钱赛道里的 PCB、ABF、CCL、连接器、光源、测试、电力和储能等环节。

## AI 周期主线判别

AI 周期研究不是找名字里带 AI 的公司，而是找技术革命进入下一阶段后，主矛盾迁移形成的新瓶颈。

每个 AI 主题先回答六个问题：

1. 结构性转变是什么，旧秩序被什么新流程替代。
2. 新瓶颈在入口、流程、基础设施、身份权限、数据上下文、物理供给还是支付结算。
3. 付款人是谁，预算从哪里来，客户为什么现在必须买。
4. 工程师、客户和财报是否同时给出信号，而不是只有媒体热词。
5. 公司是否拥有控制权、定价权和利润留存路径。
6. 未来 6-12 个月用哪个数字证明判断错了或对了。

不要把“AI 功能”自动等同于 AI 受益公司。消费品牌、广告平台、零售渠道和内容社区，要优先使用公司基本面、需求、渠道、品牌和估值框架；不能硬套工程瓶颈框架。

## 工程师信号雷达

工程师信号只用于发现未来 1-2 年可能变成企业预算的新瓶颈，不用于替代财报和估值。

强信号通常同时具备：

- 一线工程师愿意把时间投给它，不只是转发概念。
- 从 toy 走向 tool，再走向平台、基础设施或企业流程入口。
- 解决的是部署、权限、评测、回滚、观测、身份、沙箱、上下文、成本或安全这类真实工作问题。
- 出现开源 PR、企业采购、产品采用、岗位需求、云服务定价或客户案例。
- 能映射到上市公司、ETF、供应链或未来 IPO 观察对象。

弱信号包括：只在社交媒体热、只演示 demo、只让开发者喜欢、没有企业预算、没有切换成本、没有收费权、无法穿透到收入和毛利。

AI 投资链可按五层看：

| 层 | 研究问题 | 典型瓶颈 |
|---|---|---|
| L5 工作流 | AI 是否进入企业真实流程 | 权限、审计、组织流程、行业数据 |
| L4 开发和 Agent 控制面 | Agent 能否被企业安全使用 | 评测、回滚、沙箱、工具治理、身份 |
| L3 数据和上下文 | 模型如何拿到可靠上下文 | RAG、搜索、知识库、数据治理 |
| L2 推理和运行成本 | 使用量增长是否被成本卡住 | 推理成本、缓存、调度、观测 |
| L1 物理基础设施 | 算力是否被供给卡住 | GPU、HBM、网络、电力、冷却、PCB |

## 三年三倍反推边界

三年三倍反推是研究过滤器，不是收益承诺。它只能回答“这个对象是否值得继续补证据”，不能直接进入交易动作。

使用前必须补齐：

```yaml
three_year_3x_filter:
  current_market_cap:
  current_revenue:
  gross_margin:
  operating_profit_or_loss:
  free_cash_flow:
  dilution_risk:
  current_valuation_multiple:
  required_revenue_or_profit_in_three_years:
  multiple_compression_case:
  failure_data:
```

如果缺少市值、收入、利润、自由现金流、估值倍数和稀释风险，状态写 `evidence_insufficient`。如果只是“开发者喜欢”“AI 方向对”“长期空间大”，不能写三倍候选。

三倍研究候选只改变研究优先级。进入动作前仍要回到四票：`H_B` 经营、`H_R` 赔率、`H_L` 周期、`H_C` 仓位（其中 H_L 周期为软探测器，权重弱于其他三票）。

## AI 候选分类

| 分类 | 含义 | 可做什么 | 不能做什么 |
|---|---|---|---|
| 三倍研究候选 | 瓶颈、控制权、利润路径和价格仍可能同时成立 | 优先补财报、估值和失败条件 | 自动买入或加仓 |
| 瓶颈观察 | 主题真实，但公司映射或利润留存不清 | 放入观察和验证日历 | 当核心仓 |
| 趋势验证器 | 能帮助判断产业方向，但投资路径弱 | 用作证据源和对照组 | 赋予交易权限 |
| 证据不足 | 关键信息缺失 | 列下一轮问题 | 填 50% 概率或固定分 |
| 剔除 | 需求、控制、定价或财务路径失败 | 记录失败原因 | 用叙事恢复候选身份 |

## 四模型和分布指纹

新主题先判断主导模型，不要四个模型同时平均使用。

| 模型 | 用来回答 | 典型主题 | 当前边界 |
|---|---|---|---|
| Leontief 短板 | 系统由哪个最短板卡住 | GPU/HBM/CoWoS/电力/冷却 | 找瓶颈，不直接授权公司投资 |
| 泊松事件时钟 | 独立验证事件是否变密 | 招标、订单、政策落地、认证 | 只写事件强度，未校准不得写概率 |
| 幂律控制点 | 利润是否集中在少数控制者 | ABF、T-glass、HBM、平台入口 | 控制点仍要进报表和估值 |
| 贝叶斯更新 | 路线分叉如何随证据变化 | CPO/LPO/NPO、稳定币/RWA、政策链 | 未固定参考类时写 `uncalibrated` |

跨链对照时，至少比较分布指纹、瓶颈位置、定价权龙头、周期阶段和失败条件。AI、储能、铜等链的共同判别式是：需求真实不等于公司受益；真正瓶颈通常在认证、工艺、寡头集中的中下游材料或接口环节，而不一定在源头。

```yaml

  gross_margin:

  geopolitical_concentration:
  bypass_path:
```

市占率、毛利率、客户、扩产和估值缺失时，不强行填数字；状态写 `unknown`，并列为下一轮取证任务。

## 训练集误差分析

用一个 SOP 重跑旧材料时，不只看“能否覆盖”，还要做漏检分析：

```text
原文信息单元
→ 映射到 SOP 步骤
→ 区分信号和噪声
→ 记录漏检项
→ 写入 Skill 修正候选
→ 用下一组新主题验证泛化
```

文章类样本通常不能给仓位、估值或交易节奏，只能产出事件日历和证据缺口。仓位建议必须另补财报、估值、流动性和资本数据。

旧溯源稿提出“必须数字化先验/后验”的修正，已被当前概率纪律覆盖：没有参考类、期限、结算规则和历史校准时，不能填 0-100% 主观概率，只能写 `uncalibrated`。

## 训练循环和版本边界

每轮主题训练可以用 13 步闭环：

```text
SELECT 样本
→ EXTRACT 信息单元
→ ORIENT 本轮训练不是 X 而是 Y
→ MAP 九步漏斗
→ TEST 七步瓶颈测试
→ VALUE 定价权和财务路径
→ BAYES 证据方向和校准状态
→ DISTILL 可泛化判别式
→ FAIL 失败条件
→ LOG 训练日志
→ SCORE 七维自评
→ AUDIT 漏检项
→ CHECK 终止条件
```

七维自评、F1-F10 完成报告和早停条件只用于方法训练质量，不拥有交易权限。自评分、覆盖率和“训练达标”不能替代公司证据、估值、路径和资本纪律。

版本升级必须写清触发样本、修正步骤、旧规则、新规则、反证和回滚条件。禁止静默回滚；禁止用新排版覆盖旧认知。

## 必经点反问

| 问题 | 如果答案是否定 |
|---|---|
| 没有它，客户还能完成任务吗 | 不是必经 |
| 客户能自建吗 | 稀缺期可能短 |
| 竞品能免费打包吗 | 收费权弱 |
| 监管会强制开放或降价吗 | 护城河不稳 |
| 上下游会吃掉利润吗 | 股东留不住钱 |
| 扩产会不会很快到来 | 供给反噬 |

## 与“三倍候选”的边界

三倍候选池只说明右尾研究价值，不说明四票通过。没有公司基本面、估值和资本约束，不能进入 `建立验证仓` 或 `升级确认仓`。
