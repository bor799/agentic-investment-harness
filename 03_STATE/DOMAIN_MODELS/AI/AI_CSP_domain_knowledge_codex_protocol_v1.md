# AI价值迁移：大型CSP领域知识与标的研究协议 v1.0

**生效日期：2026-07-30**  
**用途：输入本地 Codex，作为 AI 投资研究的领域知识、标的筛选规则与后验更新协议。**  
**当前研究偏好：做多大型 CSP、阿里/腾讯或云消费暴露更纯的工具；暂不参与半导体，不做空半导体。**  
**重要约束：当前偏好只是待验证的研究先验，不是允许 Codex 为既定买入结论寻找理由。Codex 必须主动寻找反证。**

---

## 0. Codex的任务定义

本次不是做普通的“AI行业新闻汇总”，也不是罗列所有云计算股票。

Codex需要完成两个目标：

1. 将下述领域知识作为长期研究语义层，理解 AI 价值链为什么可能从“半导体建设端”向“云计算消费与利润兑现端”扩散。
2. 基于该领域知识，寻找最能表达这一变化的上市公司或ETF，并通过持续证据更新，判断每个标的是“逻辑成立但价格不合适”“价格便宜但业务未验证”，还是“业务、估值与交易时点同时成立”。

Codex必须分别判断四张票，不能混成一个“看好分数”：

- `H_B`：业务票——AI工程化和云消费是否真实发生；
- `H_P`：利润捕获票——该公司是否能把需求转成收入、利润和现金流；
- `H_R`：回报票——当前估值是否仍有合理的一年期回报空间；
- `H_T`：时点票——市场预期、价格结构和催化剂是否允许现在介入。

只有四张票同时达到最低标准，标的才可进入“可执行候选”；产业逻辑成立不等于立即买入。

# 第一部分：领域知识

## 1. 核心总命题

> 开放模型正在跨过生产可用线，智能权重与单纯 Token 能力趋向商品化；但运行智能所需要的有效算力、内存、存储、网络、电力，以及能够把这些资源组织成企业服务的云平台，反而可能更加稀缺。

需要区分两件事：

- **模型权重商品化**：不同模型之间的能力差距缩小，企业拥有更多模型选择，模型API的垄断溢价下降。
- **智能系统仍在Scaling**：推理时间、上下文、Agent数量、工具调用、环境反馈、长期记忆和任务持续时间继续扩张。

开放模型追赶可能削弱纯模型厂商的定价权，但不必然降低智能总消费量。真正要观察的是：

> `总智能需求增长率` 是否大于 `单位任务成本下降率`。

---

## 2. 开源模型开始获得“完整任务执行权”

Kimi K3、GLM-5.2等模型的重要意义，不只是榜单分数接近闭源模型，而是开放模型开始能够承担：

- 长上下文任务；
- 长程编码与知识工作；
- 多轮工具调用；
- 子任务拆解；
- 环境反馈；
- 多Agent并行执行；
- 端到端交付。

合理的混合Agent分工不是在每一句对话中频繁切换模型，而是：

> 强模型负责理解目标、拆解任务、关键判断、异常处理与最终验收；低成本开放模型负责执行边界清晰、可验证的完整工作单元。

因此，混合Agent的经济性不能只比较每百万Token价格，而应比较：

> **一次任务成功完成的总成本。**

至少包括：

- 输入、输出和缓存Token；
- 上下文构建与压缩；
- 工具调用；
- 子Agent数量；
- 重试和失败恢复；
- 校验成本；
- 延迟；
- 强模型升级率；
- 人类接管率；
- 最终任务成功率。

模型变便宜并不必然意味着总支出下降。模型能力提高会把原本无法自动化的任务变成可完成任务，也会提高每个任务的执行深度。

---

## 3. Coding不是单一行业，而是AI操作数字世界的接口

模型的Coding能力不只用于替代程序员。企业中的数据库、ERP、CRM、浏览器、办公软件、财务系统、供应链系统和内部平台，最终都通过代码、API、脚本、SQL和结构化工具调用改变状态。

因此：

> Coding能力跨过可用线，意味着AI开始从“回答问题”转向“可靠地操作数字世界”。

AI市场的上限不能只用程序员工资池估算。更合理的潜在市场包括：

- 企业IT支出；
- 企业服务支出；
- 软件订阅与云消费；
- 人工操作流程；
- 原本因人工成本过高而不存在的新任务；
- 由自动化频率提升而产生的新调用。

AI逐步成为软件系统之上的自动操作层，而大型CSP通常掌握企业数据、身份、权限、数据库、网络、模型托管和工作流入口。

---

## 4. Scaling没有停止，而是从单模型扩展为全系统Scaling

当前不能把Scaling等同于“预训练参数必须永远指数增加”。更完整的Scaling包括：

- 训练计算；
- 强化学习和后训练；
- 推理时计算；
- 上下文长度；
- 并行Agent数量；
- 工具调用深度；
- 任务持续时间；
- 外部记忆；
- 环境反馈；
- 多模态感知；
- 验证和自我改进循环。

投资上真正需要回答的不是“参数是否继续变大”，而是：

> 单个企业、单个用户和单项任务消耗的有效智能量是否继续增长。

如果一个深度任务从一次模型调用，升级为多个Agent持续搜索、阅读、编码、执行和验证，那么单位Token价格下降仍可能伴随总Token、GPU时长、存储、网络和平台服务消费上升。

---

## 5. 必须区分“算力”与“有效算力”

并不是所有GPU和数据中心都会持续稀缺。

容易过剩的资源包括：

- 上一代、通用且缺少客户的孤立GPU；
- 无稳定利用率的数据中心；
- 电力、网络、存储和软件栈不匹配的算力；
- 融资成本高、客户高度集中的NeoCloud；
- 缺乏企业交付、治理、安全和运维能力的纯租赁产能。

更可能保持稀缺性的资源包括：

- 前沿训练和高价值推理能力；
- 长上下文、多Agent并发所需的内存容量和带宽；
- HBM、企业级DRAM、SSD与数据搬运能力；
- 高速网络、光互连和先进封装；
- 稳定电力、冷却和已接电数据中心容量；
- 能够调度异构模型、管理数据权限并稳定服务企业客户的云平台。

有效算力不是一块芯片，而是一整套可被客户稳定调用、能够产生业务结果的系统。

---

## 6. 大型CSP是AI企业化的控制面

单纯依赖模型能力差异出售Token，护城河可能随着开放模型追赶而变薄。大型CSP更有机会通过以下环节保留利润：

- 多模型托管和路由；
- GPU、CPU和自研ASIC；
- 对象存储、数据库、向量检索和数据仓库；
- 网络与内容分发；
- 身份、权限、安全、审计和合规；
- Agent运行时、状态、记忆与工具调用；
- 评测、日志、监控和成本治理；
- 企业销售、合同、支持与迁移服务；
- 办公、广告、电商、游戏和企业软件等自有应用入口。

AI价值回收不能只观察模型API收入，应观察：

`模型能力 → 产品使用量 → 云资源消费 → 软件/平台收入 → 利润与现金流`

大型CSP的优势不是一定拥有最强模型，而是能够在模型、算力、数据、工作流、应用和企业分发的多个环节回收投入。

---

## 7. 当前阶段：利润扩散，不是硬件周期已结束

当前研究命题不是“半导体马上见顶”，也不是“云会替代半导体”。

更准确的表达是：

> AI建设端的一阶导仍然很强，但云消费、软件席位、企业合同和云利润的二阶导开始向上。价值链可能从单一建设端行情，进入建设继续增长、消费与利润加速兑现的扩散阶段。

因此当前相对价值判断是：

- 不做空半导体，因为HBM、网络和AI基础设施需求仍强，做空强一阶导资产容易被挤压；
- 暂不追半导体，因为稀缺性、涨价和扩产预期可能已被充分交易；
- 优先研究大型CSP，因为其云收入、积压订单、AI产品席位和利润率开始验证资本开支的商业回报；
- 这是一项阶段性相对价值判断，不是对云平台永久持有的承诺。

# 第二部分：截至2026-07-30的事实基线

Codex必须重新抓取并核验官方原文，不能只使用二手媒体。

## 1. Microsoft FY2026 Q4

当前已知事实：

- Azure及其他云服务收入同比增长43%；
- 公司表示客户需求仍超过可用产能，新增CPU/GPU容量在当季很快被商业化；
- Microsoft 365 Copilot付费席位超过3000万，净新增席位环比超过翻倍；
- Foundry客户达到10万，收入同比超过翻倍；
- Agent 365推出两个月后，已有接近4000万个Agent注册；
- 商业剩余履约义务约6780亿美元，剔除OpenAI后仍同比增长25%；
- 当季资本开支410亿美元，其中约三分之二用于CPU、GPU等短期资产；
- 下一季度资本开支指引超过500亿美元；
- FY2027资本开支预计继续同比增长。

正确推论：

> 微软证明了“AI云消费和应用收入开始快速兑现”，但没有证明“AI建设端已经减速”。更准确的信号是新增容量能被快速商业化，资本开支与云消费目前仍在同步扩张。

需要持续验证：

- Azure增速能否继续维持或加速；
- Copilot席位增加能否转成ARPU、利润率和现金流；
- 云毛利率是否被折旧、芯片价格和高使用量持续侵蚀；
- RPO中未来12个月可确认收入的比例；
- 资本开支增速与云收入、云经营利润增速之间的关系。

## 2. Alphabet 2026 Q2

当前已知事实：

- Google Cloud收入同比增长82%至248亿美元；
- 云经营利润88亿美元，同比超过三倍；
- 云经营利润率由20.7%提高到35.6%；
- GCP、AI解决方案与AI基础设施均为增长驱动；
- 公司仍在提高资本开支。

正确推论：

> Google Cloud是“云消费、收入和利润同时加速”的强证据，但其中包含TPU系统销售，需要剔除硬件销售影响，判断核心云消费是否仍然加速。

## 3. Alibaba FY2026末季

当前已知事实：

- 云智能集团外部收入增长加速至40%；
- AI相关产品收入连续第11个季度实现三位数同比增长；
- AI相关产品占云外部收入约30%；
- Model Studio客户数量同比约增长八倍。

正确推论：

> 阿里是当前中国上市公司中，表达“开放模型、MaaS、AI算力与企业云消费”最直接的大型CSP之一。

需要验证：

- 云收入是外部高质量公共云增长，还是低毛利项目收入；
- AI收入占比提升是否伴随云EBITA和自由现金流改善；
- 模型价格竞争是否导致收入增长但利润留存不足；
- 电商投入、即时零售等其他业务是否抵消云利润增长；
- 估值是否已经充分反映云增长恢复。

## 4. Tencent 2026 Q1

当前已知事实：

- Business Services收入同比增长20%；
- 增长由国内外云服务、AI相关需求、较有利的定价环境及电商技术服务共同驱动；
- 公司总体自由现金流仍强，能够支撑AI投入；
- 腾讯云只是腾讯价值的一部分，腾讯同时暴露于游戏、广告、支付、金融科技和社交生态。

正确推论：

> 腾讯是“AI改善平台综合变现”的标的，不是纯云计算标的。研究时必须把云贡献与广告、游戏和其他业务贡献拆开。

# 第三部分：投资假设树

## H1：开放模型跨过生产可用线

成立信号：

- 开放模型在长程编码、工具调用、自动化和知识工作上持续缩小与闭源模型的差距；
- 企业实际部署数量增加；
- 任务成功率提高；
- 强模型升级率和人类接管率下降；
- 混合Agent单任务总成本下降。

反证：

- 榜单提升无法转成真实任务完成率；
- 长任务失败率、重试率和人工接管率居高不下；
- 开放模型只在低价值任务中使用；
- 数据安全、部署和运维成本抵消Token价格优势。

## H2：成本下降会扩大总智能消费

成立信号：

- API、Agent、Copilot和云AI调用量增长快于单价下降；
- 上下文长度、任务持续时间和Agent数量增加；
- 企业从试点进入生产；
- AI工作负载带动云、数据库、存储、安全和网络共同增长。

反证：

- 单位成本下降，但总消费金额停滞；
- 使用集中于短问答，企业生产负载没有扩张；
- AI收入只是从传统云收入内部迁移，没有带来新增量。

## H3：大型CSP能捕获AI价值

成立信号：

- 云收入和增速上升；
- AI产品收入占比上升；
- RPO、backlog和大型合同增加；
- 云经营利润与利润率改善；
- 新增容量快速被商业化；
- 数据库、安全、Agent平台和应用收入同步增长；
- 自由现金流能够覆盖或逐步接近资本开支。

反证：

- CapEx、折旧和融资成本增长持续快于云毛利；
- 云收入增长但利润率下降；
- 模型价格战使收入有量无价；
- 客户能够轻易绕开平台直接使用模型；
- 大客户集中、合同取消或产能利用率下降。

## H4：当前阶段云平台的风险回报优于半导体

成立信号：

- 云收入、利润和订单预期持续上修；
- 半导体收入仍增长，但增速、涨价预期或估值开始钝化；
- CSP相对半导体出现盈利预测上修和相对强度改善；
- CSP估值尚未完整计价AI商业化；
- 市场开始奖励“投入回报”而非单纯“资本开支规模”。

反证：

- 半导体订单和利润继续大幅上修，估值仍不贵；
- 云收入加速主要来自一次性硬件销售或会计口径；
- 云毛利和自由现金流被CapEx、折旧和价格竞争明显侵蚀；
- 云平台估值已提前透支多年增长。

## H5：中国CSP能够复制或形成自己的商业化路径

成立信号：

- 阿里云、腾讯云等外部收入加速；
- AI产品占比、客户数、MaaS/Agent收入和公共云收入提升；
- 价格竞争减弱，单位经济改善；
- AI收入不仅来自内部关联业务；
- 云利润、EBITA和现金流改善；
- 政策与企业采购支持国内模型和国内云部署。

反证：

- 低价竞争长期压制利润；
- AI收入主要为内部结算或低质量项目；
- 企业云预算增长不足；
- CSP资本开支不能转成外部收入；
- 监管、宏观或竞争使估值和盈利长期受压。

# 第四部分：标的分类与研究边界

Codex先分类，再比较，不能把不同商业模式混在一个排名中。

## A类：超大型CSP与企业控制面

种子池包括但不限于：

- Microsoft；
- Alphabet；
- Amazon；
- Oracle；
- Alibaba；
- Tencent；
- 百度；
- 中国电信、中国移动、中国联通。

研究重点：

- 企业客户与分发；
- 公共云增长；
- AI收入；
- 数据库、数据、安全和Agent平台；
- CapEx生产率；
- 云利润和现金流；
- 估值与预期差。

## B类：平台型AI受益公司

拥有应用入口，可以通过广告、电商、办公、游戏或企业软件回收AI成本，但云并非唯一主业。

研究时必须拆分：

- AI对核心业务的增量；
- 云的独立贡献；
- 其他业务对估值和现金流的影响。

## C类：NeoCloud或纯AI基础设施运营商

例如NBIS等高弹性标的。

必须额外验证：

- 已接电容量；
- GPU利用率；
- 客户集中度；
- 融资成本；
- 合同期限；
- take-or-pay条款；
- 芯片折旧；
- 新旧GPU替代；
- 资本开支和自由现金流。

该类单独放入高风险观察池，不与大型CSP用同一估值框架。

## D类：ETF

ETF不能按名称判断，必须穿透持仓。

对每只“云计算”“数字经济”“中概互联网”ETF计算：

- 大型CSP与互联网平台权重；
- 半导体、光模块、服务器和硬件权重；
- 软件和SaaS权重；
- 前十大集中度；
- 阿里、腾讯、百度、中国电信等目标标的权重；
- 过去一年换仓和指数规则。

当前策略要求“云消费端表达”，因此默认规则：

- 硬件、半导体、光通信和服务器合计权重不高于20%：可视为较纯云/平台表达；
- 20%—35%：标记为混合工具；
- 高于35%：不得称为“云消费端纯表达”。

# 第七部分：后验更新协议

## 1. 不允许使用一个总分代替四张票

每项假设分别维护：

| 字段 | 说明 |
|---|---|
| hypothesis_id | H_B / H_P / H_R / H_T |
| prior_probability | 更新前主观概率，必须给区间 |
| evidence | 新证据 |
| source | 官方财报、监管文件或高质量原始资料 |
| evidence_group | 需求、收入、利润、CapEx、估值、价格、宏观 |
| likelihood_ratio | 证据在假设成立与不成立时出现的相对可能性 |
| dependency_group | 与哪些证据高度相关 |
| posterior_probability | 更新后的概率区间 |
| confidence | calibrated / bounded_unknown / uncalibrated / not_applicable |
| next_check | 下一个复查事件和日期 |
| invalidation | 失效条件 |

## 2. 似然比使用区间，不做伪精确

默认参考：

- 弱正证据：LR 1.1—1.3；
- 中等正证据：LR 1.5—2.5；
- 强正证据：LR 3—6；
- 决定性正证据：LR >10；
- 负证据使用对应倒数。

同一财报中的收入、RPO、客户数和管理层表述往往相关，不能独立连乘。对同一依赖组的累计LR设置上限，并在报告中说明依赖关系。

后验计算：

`posterior_odds = prior_odds × likelihood_ratio`

`probability = odds / (1 + odds)`

Codex必须同时保留低、中、高三种LR情景，输出概率区间，不能只给一个小数。

## 3. 状态定义

- `uncalibrated`：缺少足够历史基线，概率数字不可用；
- `bounded_unknown`：能够给方向和范围，但证据不足以精确；
- `calibrated`：拥有可追溯数据、历史基线和稳定口径；
- `not_applicable`：该指标不适用于此商业模式。

## 4. 决策门槛

建议默认门槛，可被本地交易宪法覆盖：

- `H_B ≥ 70%`：行业和业务需求得到较强验证；
- `H_P ≥ 65%`：公司利润捕获路径较清晰；
- `H_R ≥ 60%`：当前价格仍有合理风险回报；
- `H_T ≥ 55%`：允许建立方向仓，但不代表可一次性重仓。

只要`H_R`或`H_T`不足，输出应为“逻辑成立，等待价格或催化”，而不是降低研究标准强行推荐。

# 第八部分：交易执行与风险纪律

产业判断、标的判断和仓位判断必须分开。

该偏好不允许演变为：

- 为明天加注寻找确认性材料；
- 因为错过存储上涨而追逐云平台；

- 用“长期AI正确”替代一年期回报判断；
- 用单日普涨认定趋势反转；
- 用一次财报认定永久商业模式胜利。

交易执行继续遵守：

1. 优先寻找业绩已经证明AI需求兑现、且明显超过市场预期的公司；
2. 市场下跌时，比较当前价格与业绩公告前价格；
3. 等待价格不再创新低或相对强度转稳；
4. 买尚未充分反弹、但盈利预测仍上修的标的；
5. 普涨不等于趋势反转，必须观察板块内部的持续领涨与基本面对应；
6. 输出分批触发条件，不输出“打满”“梭哈”或单点最低价预测；
7. 入场前冻结thesis、验证数字、失败条件、仓位职责和复查日期；
8. 入场后只有独立新证据可以修改thesis，不能因成本锚、恐惧或兴奋修改。
