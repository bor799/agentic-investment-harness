## 0. 任务定位

这不是又一篇 AI 算力链报告。前一轮（2026-06-17 凌晨 01:20）已经产出 `260617AI算力连接与材料瓶颈_挖掘端框架.md`（11KB 萃取版 + 25KB 长报告）。

本轮的目标是**事后审计**：

```text
两篇原文 → 信息单元抽取 → 映射到 SOP v1.0 → 找漏检项 → 推 v1.1 修正
```

这是 ML 训练里的"误差分析"——不是再跑一遍模型，而是看上一轮模型哪里漏了。

## 4. SOP v1.0 在跑这两篇文章时的漏检项

把"信息单元已抽取但 SOP 没有专门步骤处理"的项列出来。每条漏检 → 推一个 v1.1 修正项。

### 漏检 #1：S2 付款人确认弱命中

- **现象**：两篇文章提了"AI CapEx"（A05、B03），但没具体拆"谁付钱、预算从哪来、付费刚性"。
- **SOP v1.0 缺口**：S2 步骤定义不够具体，没有"付款人优先级清单"。
- **v1.1 修正项**：S2 加"付款人优先级表"——政府/企业/消费者/产业链下游，每种付款人的预算可见度、刚性程度、付费周期。

### 漏检 #2：S9 节奏与仓位 0% 命中

- **现象**：两篇文章不给交易建议（研报纪律）。
- **SOP v1.0 缺口**：S9 完全依赖外部数据（财报、估值、IVR），文章类训练样本天然无法覆盖。
- **v1.1 修正项**：S9 标注"输入源"——文章类样本只能产出"泊松事件日历"，仓位建议需要补充财报和估值数据。

### 漏检 #3：标的"市占率/CR3/估值"未覆盖

- **现象**：B24-B30 给了 7 家公司，但都没给市占率、CR3、估值、毛利率。
- **SOP v1.0 缺口**：S8 标的映射的输出格式不够严格，没有"必填字段"。
- **v1.1 修正项**：S8 输出格式加"必填字段表"——公司名/代码、市占率、毛利率、PE、主要客户、扩产计划、瓶颈强度评分。

### 漏检 #4：贝叶斯更新表未给出"先验概率数字"

- **现象**：前一轮产出（`260617AI算力连接与材料瓶颈_挖掘端框架.md`）只给了定性的"上调/下调"，没给数字化的概率。
- **SOP v1.0 缺口**：§5 贝叶斯更新表定义了"先验 P(H)、似然、后验"模板，但没强制要求数字化。
- **v1.1 修正项**：§5 加"数字化要求"——每条判断的先验和后验必须是 0-100% 的数字，定性词（"高"/"中"/"低"）不允许。

### 漏检 #5：地缘政治维度完全缺失

- **现象**：两篇文章基本不讨论美中日韩在半导体/材料/电力设备上的博弈。但 ABF 膜（味之素=日本）、HBM（SK 海力士=韩国、三星=韩国、美光=美国）、T-glass（日东纺=日本）都高度依赖地缘。
- **SOP v1.0 缺口**：没有"地缘政治维度"作为评估因子。
- **v1.1 修正项**：S5 供给评估加第 6 维——"地缘集中度"（某环节是否集中在单一国家/地区，制裁风险）。

### 漏检 #6：扩产反噬时点未量化

- **现象**：B14 说"PCB/ABF/CCL 扩产过快会反噬"，但没给"2027-2028 哪个季度反噬"的时点。
- **SOP v1.0 缺口**：S5 供给评估的"扩产周期"维度只看"扩产需要多久"，没看"扩产完成后多久反噬"。
- **v1.1 修正项**：S5 加"反噬时点"——扩产完成后 X 季度，价格开始下行。需要从历史周期数据校准 X。

### 漏检 #7：客户认证周期未明确分级

- **现象**：B13 说"味之素 ABF 业务 30 年没人能撼动"，但没拆"哪些客户认证需要多久"。
- **SOP v1.0 缺口**：S5 的"认证周期"维度只给"长/短"，没分级。
- **v1.1 修正项**：S5 加"认证分级"——Tier 1 客户（NVIDIA、AWS、Google）认证周期、Tier 2（阿里、字节、腾讯）认证周期、Tier 3（小客户）认证周期。

### 漏检 #8：客户集中度风险未讨论

- **现象**：B24-B27 多家公司高度依赖 NVIDIA 或 AWS 单一客户。如果客户切换供应商，公司业绩崩。
- **SOP v1.0 缺口**：S6 七步测试的 Control 测试提到"客户集成"，但没量化"客户集中度风险"。
- **v1.1 修正项**：S6 Control 测试加"客户集中度阈值"——单一客户占比 > 30% 标记为"客户集中度风险"，需补"客户分散计划"。

## 6. 训练集溯源结论

### 6.1 SOP v1.0 的强项（保持）

- **覆盖率 100%**：50 个信息单元全部能映射到 SOP 某步或某模型
- **§4 反简单叙事 + S4 逆向溯源**：两步对工程参数密集的研报最有效
- **四思维模型**：Leontief/泊松/幂律/贝叶斯每个都有真实命中
- **Transmission 测试**：天然适合"需求→传导→公司"的链条判断

### 6.2 SOP v1.0 的弱项（v1.1 必修）

- **S2 付款人**：定义太弱，需要加优先级表
- **S8 标的格式**：太松散，需要必填字段表
- **§5 贝叶斯**：定性，需要数字化
- **S5 供给评估**：缺地缘维度、缺反噬时点、缺认证分级
- **S6 Control 测试**：缺客户集中度阈值

### 6.3 SOP v1.0 的盲区（v2.0 候选）

- **训练集太干净**：两篇研报几乎无噪声。真实世界文章（社交媒体、采访稿、政策解读）有大量情绪和噪音，SOP 需要"信号过滤"步骤 → v2.0 候选
