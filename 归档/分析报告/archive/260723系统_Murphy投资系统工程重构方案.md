# Murphy 投资系统工程重构方案

> V2.1 第一阶段交付：只做工程审计，不重写核心哲学，不迁移现有内容，不替 Murphy 裁决“道”。

## 先说人话

**今天发生了什么：**我完整扫描了股票投资库的 `632` 个文件，其中 `611` 个是 Markdown。当前系统已经有大量研究、证据和方法，但“道、术、State、Case、Evidence、自动化”没有被稳定隔开。本轮只新增了这份审计报告，现有核心文件没有修改。

**为什么重要：**现在最大的风险不是找不到更多投资方法，而是权限串层：一次交易、一个 AI 推断、一个实时市场判断，可能沿着现有维护协议被写成“Murphy 已吸收的稳定哲学”。这样会让系统越来越完整，却越来越难分辨哪些话真是 Murphy 裁决过的。

**现在做什么：**先冻结核心层的自动升级。本报告交给后续 Agent 执行时，按第七章的权限矩阵处理：

- 工程治理由 Agent 按方案直接执行，不逐项占用 Murphy；
- “术”可以根据证据和 Case 迭代，但不能自动变成“道”；
- 只有 MINDSET 的长期命题和个人 Constitution 的 Guardrail 需要 Murphy 裁决。

本轮仍只修订执行计划，不执行迁移，不重写 `MINDSET` 或 `CONSTITUTION`。

---

## 0. 审计边界与判定方法

### 0.1 本轮做了什么

- 读取全库文件清单、主要正文、模板、脚本和历史版本；
- 按实际内容判断职责，不按文件名判断；
- 统计重复、占位文件、来源标记、链接和时间污染；
- 把现有方法拆成“可保留的术、需要合并的术、缺失的术、没有决策价值的旧机制”；
- 为全部 `632` 个文件建立迁移规则；
- 整理候选认知的原始来源、冲突与确认状态；
- 发现冲突，但不替 Murphy 裁决。

### 0.2 本轮没有做什么

- 没有生成“Murphy 十大投资哲学”；
- 没有把重复次数当成认同票数；
- 没有把 AI 报告中的第一人称自动当成 Murphy 原话；
- 没有把成功方法升级成“道”；
- 没有改写 `交易宪法/CONSTITUTION.md`；
- 没有改写 `交易宪法/MURPHY_CURRENT_COGNITIVE_MODEL.md`；
- 没有移动、合并或删除任何旧文件；
- 没有改变仓位、概率、参数和交易动作。

### 0.3 四种确认状态

后文只使用以下状态，避免“看起来像确认”：

| 状态 | 含义 | 能否进入 MINDSET / CONSTITUTION |
|---|---|---|
| `Murphy 已明确确认` | 有可定位的直接确认，且确认对象就是这条长期命题 | 可以，但仍需确认表述 |
| `当前任务候选` | Murphy 明确说它是候选核心认知 | 不可以，先讨论 |
| `历史人机共建` | 有 Murphy 输入，但完整命题由 AI 整理或扩写 | 不可以，需重新确认 |
| `纯 AI / 来源不足` | 主要来自 AI 推断、外部材料或来源无法定位 | 不可以 |

本任务已经明确确认的是**治理权限**：

> 道由 Murphy 裁决，术允许系统进化；任何下层内容不得自动向上晋升。

这是一条系统治理规则，不等于一条投资哲学命题。

### 0.4 “逐项迁移”的表达方式

全库共有 `632` 个文件。逐个写 `632` 行会让方案不可读，因此第六章使用“**互斥路径族 + 数量 + 明确例外**”：

- 每个现有文件只命中一个路径族；
- 各路径族数量之和等于 `632`；
- 同一路径族使用同一迁移动作；
- 需要特殊处理的文件单独列名。

这仍是逐文件可执行的迁移地图，但本轮不执行。

# 二、职责混乱地图

## 2.1 P0：权限串层

这是本次重构最需要先处理的问题。

### A. Constitution 超出 Guardrail + Router

当前 `交易宪法/CONSTITUTION.md` 同时包含：

- “Murphy 是什么样的交易者”的人格结论；
- 能力圈和弱点；
- 投资目标顺序；
- 九条红线；
- 模块优先级；
- 完整证据更新法；
- 估值和财务分析方法；
- 路由；
- 认知模型维护规则。

V2.1 已明确：新 `CONSTITUTION` 只保留 `Guardrail + Router`。因此当前第一、二、四、五、七、八条不能自动原样保留；它们分别应被审计为候选认知、Trading System、Evidence Meta 或历史版本。

### B. 认知模型把“AI 观察到的 Murphy”写成“Murphy”

`交易宪法/MURPHY_CURRENT_COGNITIVE_MODEL.md` 同时使用：

- “Murphy 当前相信什么”；
- “尚未完全说出口但反复出现的认知模式”；
- “当前高权重信念”；
- 当前市场、持仓和公司结论；
- 错误人格、能力圈和版本更新。

“未明说但反复出现”最多只能生成**候选命题**。它不能被写进正式 MINDSET，也不能因为 AI 在多个文件里重复就提高确认状态。

### C. 命题账本用“已吸收”替代 Murphy 裁决

`交易宪法/_meta/认知命题证据账本.md` 把 `PH-01`、`PH-02`、`PH-03` 标记为“已吸收，高”，并把市场机制、错误模式、世界模型、持仓状态放进同一账本。

这份账本对“同根信息不能重复计票”的提醒有价值，但“已吸收”属于越权标签。V2.1 生效后，这些标签只能理解为**历史 AI 判断**，不能继续作为 Murphy 已确认的证据。

### D. 维护协议允许系统自行晋升哲学

`交易宪法/skills/07_认知模型维护协议.md` 把稳定哲学、世界模型、案例和来源治理放进一个流程，并允许通过多个案例或模型证据修改稳定层。

新规则必须改为：

```text
系统可以提出候选
→ 系统不能自行晋升
→ 只有 Murphy 明确裁决才能进入 MINDSET / CONSTITUTION
```

### E. 单次 Case 被写成“新增硬规则”

`📈 个人交易手册.md` 在 501096 等案例后直接生成“新硬规则”。这些规则可能有用，但单次 Case 只能生成观察或候选，不能直接生成人格或 Constitution。

### F. AI 操作规则与个人哲学没有分开

根目录 `AGENTS.md` 是当前 Codex 必须遵守的操作规则，包括反方审查、四票、冷静期和 GPT 权限。它对 AI 当前工作有效，但“AI 必须这样做”不自动等于“这就是 Murphy 的 MINDSET”。

正确关系应是：

```text
AGENTS.md = AI 当前操作权限
CONSTITUTION.md = Murphy 明确确认的长期禁止事项 + Router
MINDSET.md = Murphy 明确确认的长期认知
```

三者可以互相引用，但不能互相冒充。

## 2.5 P1：Case 被写成人格

1. 501096 的一次退出未闭环，被直接写成长久行为人格；

```text
Case 记录当时发生了什么

→ 找反例和重复样本
→ 进入候选命题

```

## 4.3 建议保留并合并的“术”

### A. 主决策流

```text
问题分类
→ 时间范围与工具约束
→ 宏观/政策仅确定研究环境
→ 产业付款人与供需
→ 必经点、绕开路径和稀缺持续期
→ 公司收费权是否进入报表
→ 市场隐含了什么预期
→ 估值、回报路径、资本约束
→ 只输出六档动作
→ Case 记录与方法反馈
```

### B. 六个必须独立的核心 Skill

1. `LIQUIDITY_TRANSMISSION`：政策与资金怎么传；
2. `STRUCTURAL_CHANGE_BOTTLENECK`：新秩序和必经点；
3. `INDUSTRY_SUPPLY_DEMAND`：产业链、供给反应和利润池；
4. `COMPANY_FUNDAMENTALS`：公司怎么真正赚钱；
5. `EXPECTATIONS_VALUATION`：现实、预期和价格；
6. `BEHAVIOR_REVIEW`：人在什么状态下容易改写证据。

其他 Skill 都应是专项插件，而不是继续扩充一个巨型主框架。

## 4.4 当前缺失的“术”

| 缺口 | 为什么缺 | 最小补法 |
|---|---|---|
| 明确的期限合同 | 十年经营、三年判断、一年交易、1—3 月事件并列 | 每次研究先写 `business_horizon / thesis_horizon / execution_horizon / review_date` |
| 市场预期账本 | “现实—预期差”目前只有口号，没有可核验分母 | 记录当前一致预期、价格隐含情景、可改变预期的下一事件 |
| State 失效机制 | 当前判断不断进入长期页面 | 所有 State 必填 `data_cutoff / expires_at / refresh_trigger` |
| 单一公司 dossier | 公司 Evidence 被拆成六个重复模板 | 一家公司一个目录、一个主索引，Evidence 与 State 分开 |

|---|---|---|---|---|
| `道` | 投资本质、长期原则、长期不可违背边界 | Murphy | 搜索原文、整理候选、找反例、展示演化、记录裁决 | 自行确认、润色后冒充 Murphy 原话、用重复次数代替确认 |
| `术` | 把道应用到宏观、产业、企业、市场、估值和交易的方法 | 系统 | 根据 Evidence 和 Case 合并、拆分、试验、升级、降级或退役 Skill | 违反已确认的道；把有效方法自动升级成道 |
| `治理` | 文件职责、目录、权限、版本、状态、TTL、归档、路由和来源标签 | Codex | 按本方案直接设计和执行，并保留变更记录 | 为普通工程参数反复询问 Murphy；借治理之名改写道 |

核心关系：

> 道规定方向和边界，术负责认识现实；术依道而生，并接受现实不断修正。

### 执行 Agent 的第一条判断

```text
这是“道”吗？
├─ 是：已有 Murphy 明确裁决记录 → 按裁决执行
│      没有裁决记录 → 进入 Philosophy Inbox，不写 MINDSET
└─ 否：是“术”还是“治理”？
       ├─ 术 → 按证据和 Case 迭代，记录版本与失败条件
       └─ 治理 → 直接执行，记录迁移和回滚路径
```

不要把“需要判断”误解成“都需要问 Murphy”。

## 7.2 六项治理裁决：直接执行，不再逐项请示

以下已经是本计划的确定性工程指令。

| 对象 | 必须执行的动作 | 怎样算完成 |
|---|---|---|
| Constitution | 重构为 `Guardrail + Router`；人格/哲学进 MINDSET，方法进 Trading System/Skills，证据协议进 Evidence/Research Protocol，版本和来源进 Meta | 新 Constitution 只剩 Guardrail 和有效路由；没有 State、公司分析、证据正文和方法展开 |

| 命题账本 | 把“证据强弱”和“Murphy 是否认同”拆成两个字段 | 每条命题同时有 `evidence_status` 和 `murphy_status`，旧状态有迁移说明 |

### 命题双状态的固定枚举

```yaml
evidence_status: strong | mixed | weak | contradicted
murphy_status: unreviewed | candidate | confirmed | rejected
```

迁移规则：

- 历史“高置信、已吸收、已采纳”不得直接映射成 `confirmed`；
- 有 Murphy 可定位的明确裁决，才可写 `murphy_status: confirmed`；
- 没有明确裁决时，按原始来源写 `unreviewed` 或 `candidate`；
- 不删除旧标签，放进 `legacy_status` 或迁移日志，避免伪造历史。

### Case 进入 Philosophy Inbox 的必要条件

只有一个模式同时满足以下四项，才可从 Case Gym 进入 Philosophy Inbox：

1. 在多个相互独立的案例中反复出现；
2. 有明确因果机制，不只是结果相似；
3. 已做反例审查；
4. 在不同市场状态下仍有解释力。

不设置“满三个案例自动晋升”之类机械阈值。满足四项也只获得候选资格，仍不能自动进入 MINDSET。

## 7.3 已给出的投资认知裁决：Agent 不再重新辩论

以下内容来自 Murphy 本轮提供的修订文本。它们是后续重构的方向性输入。执行 Agent 应保持其核心含义，不得另造一套平行哲学；正式写入 MINDSET 时仍需保留对应裁决来源。

| 主题 | 道的边界 | 术的执行要求 |
|---|---|---|
| 政策与产业 | **政策可以改变水流，但不能替利润背书。** | 区分需求侧、供给侧、产业基金、信贷融资；继续验收到真实需求→供需→订单→利润→现金；同时检查政策是否刺激供给、消灭稀缺 |
| 长期新秩序与周期 | **看十年，想三年，投一年。** | 长期看方向，1—3 年找必经之路，约一年找最可能兑现的现实变化与预期差；一年是研究与兑现窗口，不是机械持有期限 |
| 共识兑现 | 不新增“共识形成即卖出”；保留**股票赚未来现实与当前预期之间的差** | 原 thesis 被充分定价后，以当前价格重新做一次独立判断；旧 thesis 兑现不等于必须清仓，新逻辑必须独立成立 |
| 成长与估值 | **增长不是价值，能被股东留下的增长才是价值。** | 检查增速×持续时间×增量利润率×资本效率×股东留存；高增速不能自动推出高估值合理 |
| 产业、资金、情绪 | **先认清自己参加的是什么游戏。** | 产业事实、资金趋势、情绪拥挤分别维护；用什么逻辑买入，就用什么证据验证和退出；亏损后不得把交易改写成长投 |
| 生存与右尾 | **先保证长期生存，再等待幂律机会。** | 仓位、定义损失、期权、barbell 等留在术中迭代；追求右尾不能以左尾出局为代价 |
| 必经之路 | **必经不等于好投资。** | 每个必经点检查扩产周期、复制时间、客户自建、技术替代、竞争进入、利润留存和供给反噬时钟，并走完必经→稀缺→收费权→利润留存 |
| 能力圈外用指数 | 属于术，不单列为哲学；**ETF 可以降低公司选择错误，不能消除行业判断错误。** | 只有行业 Beta 有把握、公司 Alpha 无法判断时才使用；分散不得写成低风险 |
| 创始人与财务 | **人可以解释未来，数字必须验证过去。** | 创始人、文化和组织只生成持续性假设；资本配置、历史兑现、利润和现金流负责验证 |
| 不行动与退出 | **不行动是否安全，取决于是否已经承担风险。** | 未持仓不行动是保留选择权；持仓后失败条件触发，不行动是继续承担风险；具体冷静期和订单规则归 Trading System |
| 贝叶斯 | **观点必须随证据更新。** 允许不知道，也允许改变 | 有参考类和样本才概率化；否则只写增强、削弱、未改变或推翻，不用数字制造确定性 |
| 价格归因 | Mindset 保留简单表达：**产业决定锚，资金形成趋势，情绪制造偏离。** | “内在价值/流动性溢价/风险偏好”保留为价格归因 Skill，不再形成第二套平行哲学 |

## 7.4 Constitution 重构合同

新个人 Constitution 只包含：

1. 长期 Guardrail；
2. Router。

Guardrail 以以下七条为重构基线：

| ID | 长期 Guardrail | 不应写入 Constitution 的细节 |

| `G-07` | **不让过去拥有今天的投票权：**成本价、沉没投入和过去判断不能决定今天是否继续持有 | 个别交易 Case 和实时持仓 |

AI 权限、未成交不得写成成交、文件版本、来源标签和自动化权限全部留在 `AGENTS.md` 或 System Governance，不进入个人 Constitution。

旧 Constitution 中未进入这七条基线的内容不等于删除：退出触发、现金角色、四票、冷静期等先下沉到 Trading System / Skills；AI 权限下沉到 `AGENTS.md`。除非 Murphy 后续明确确认，否则它们不再拥有个人 Constitution 权限。

- 只有 `Guardrail` 和 `Router` 两种正文职责；
- Guardrail 只保留长期边界，不含公司名、当前持仓、市场判断和会过期参数；
- Router 中每个目标文件真实存在且职责唯一；
- 七条基线没有被 Skill 表格重新膨胀；
- 新增、删除或改变 Guardrail 核心含义时，有 Murphy 的明确裁决记录；
- AI 权限和文件治理没有混入个人投资宪法。

## 7.5 MINDSET 的前台与后台

MINDSET 不按 `C-01`、`C-02` 等数据库编号批量展示，也不要求 Murphy 审核一张巨大表格。

前台讨论只围绕少数根本问题：

1. 利从哪里来？
2. 变化如何变成利润？
3. 为什么现实与价格会分离？
4. 人为什么容易犯错？
5. 如何在不确定中长期生存？

后台继续维护候选编号、来源、Evidence Status、Murphy Status、反例和演化记录。

### MINDSET 验收标准

- 只出现 `murphy_status: confirmed` 的长期命题；
- 每条命题都能回链到 Murphy 的裁决记录；
- 不含公司结论、当前市场、仓位、参数和操作清单；
- 不使用“Murphy 尚未说出口但其实相信”之类 AI 越权表述；
- 前台简洁，证据和争议留在后台；
- 新 Case、新文章和 Skill 更新不会自动修改 MINDSET。

## 7.6 新材料吸收协议

以后任何文章、播客、研报、财报、语音或外部材料进入后，不以“写完摘要”为完成标准，必须回答：

> 它改变了系统什么？

固定流程：

```text
新材料
→ 提取真正新增的命题、事实、机制或反例
→ 与现有内容去重
→ 判断是新证据 / 新机制 / 反例 / 同根重复
→ 选择影响层级
→ 写入目标位置并生成吸收回执
```

只允许四种影响结果：

| 结果代码 | 什么时候使用 | 写到哪里 | 权限边界 |
|---|---|---|---|
| `METHOD_UPDATE` | 提供可复用方法、因果机制或新检查项 | Trading System / Skill | 可直接更新术；不得自动改道 |
| `STATE_UPDATE` | 改变当前宏观、行业、企业、资金或持仓状态 | State | 必须有 data cutoff / TTL |
| `PHILOSOPHY_CANDIDATE` | 挑战或强化长期底层认知 | Philosophy Inbox | 只能候选，等待 Murphy |
| `NO_INCREMENT` | 同根重复，或不能改变任何判断 | 回执记录“无新认知” | 不新增规则，不制造新概念 |

材料原文或来源指针按 Evidence 规则保存。Evidence 是来源层，不等于第五种“认知更新”。

### 极简吸收回执

```yaml
new_information:
change: strengthen | weaken | revise | overturn | none
affected_item:
result: METHOD_UPDATE | STATE_UPDATE | PHILOSOPHY_CANDIDATE | NO_INCREMENT
write_to:
source:
```

自然语言前台只显示三行：

- **新东西是什么：**
- **改变了什么：**
- **写到哪里：**

## 7.9 失败条件与策略边界

7. 把 AI 权限、成交确认和文件版本写进个人 Constitution；
8. 用案例数量阈值代替因果、反例和跨状态审查；

12. 只完成搬文件，没有证明权限边界和路由真实生效。

> 道由 Murphy 裁决。

# 八、全局迁移验收标准

本章检查全库迁移是否完整；第七章检查裁决权限和知识进化机制是否正确。两章必须同时通过。

## 8.1 结构验收

- 632 个旧文件全部有迁移记录；
- 每个新文件只有一个 `primary_role`；
- HOME 能路由到道、术、State、Case、Evidence；
- 旧路径有重定向或历史索引；
- 本地链接无新增断链。

## 8.2 权限验收

- MINDSET 每条命题都有 Murphy 明确裁决记录；
- Constitution 只含 Guardrail + Router；
- Philosophy Inbox 明确 `decision_authority: none`；
- Case、Evidence、State 和 Automation 无法自动写入 MINDSET / CONSTITUTION；
- AI 生成的第一人称文本不会被标成 Murphy 原话；
- “已吸收、采纳、最高效力”只在有 Murphy 决策记录时出现。

## 8.3 “术”验收

- 每个方法只有一个 canonical 入口；
- 旧版本明确 `superseded_by`；
- 方法参数与长期原则分离；
- 每个 Skill 写清输入、输出、不能证明什么和失败条件；
- 方法有效性用真实 Case 结算，不用 AI 自评；
- 方法可以升级、降级、拆分和淘汰，但不能修改道。

## 8.4 阅读体验验收

任何新文章开头都先回答：

1. 发生了什么；
2. 为什么重要；
3. 现在做什么或不做什么。

后台可以复杂，前台只展示：

```text
结论
→ 原因
→ 要验证的数字
→ 什么情况说明我错了
→ 六档动作之一
```

# 九、最终审计结论

当前库不是“缺一套投资哲学”，也不是“缺更多研究报告”。

它已经积累了三类有价值的东西：

1. Murphy 的原始表达和真实 Case；
2. 可以继续进化的分析方法；
3. 大量公司、行业和工具 Evidence。

真正需要重构的是它们之间的权限关系：

```text
原始表达不等于已确认哲学
AI 重复不等于独立证据
方法有效不等于长期原则
State 不等于认知
Case 不等于人格
Evidence 不等于信念
```

建议先做“减权限”，再做“搬文件”：

- 把当前认知模型、命题账本和规则裁决表视为历史 AI 审计材料；
- 把 Constitution 收缩为 Murphy 明确确认的 Guardrail + Router；
- 把所有候选放入无决策权限的 Philosophy Inbox；
- 让 Trading System 和 Skills 自由进化；
- 让 State 会过期、Case 可结算、Evidence 可追溯；
- 最后再由 Murphy 少量、逐条地写入 MINDSET。

本轮没有重写任何核心文件，也没有执行迁移。

> 道由人定，术由系统练。  
> 道要少，术要活。  
> 先把权限放对，再讨论内容写得多漂亮。
