# 第一部分：投资之道是 AI 研究的最高约束

## 1.1 最短版本

> **看十年，想三年，投一年。**
>
> **顺大势，找窄门，赚预期差，先保命。**

[P0·用户原始判断]

这两句话不是一句口号，而是整个 AI 研究知识层的边界：

- **看十年**：判断世界真正向哪里变化，例如智能商品化、Agent、Physical AI、真实世界劳动被机器接管。
- **想三年**：判断新秩序必须经过哪些产业路径，例如 GPU、HBM、光互联、电力、推理基础设施、端侧计算、传感器和数据闭环。
- **投一年**：只下注未来约一年内可能被订单、收入、毛利、现金流、资本开支或市场资金验证的变化。

长期趋势是地图，三年路径是产业链，未来一年兑现才是可下注的路段。

## 1.2 投资不是寻找静态便宜，而是投资变化

[P0·用户原始判断]

> **投资是投变化。没有变化，就很难有重新定价。**

AI 很重要，不构成投资理由；AI 将长期提高生产率，也不自动证明某个阶段的芯片、云、软件或机器人公司值得买。

研究必须继续追问：

```text
世界发生了什么真实变化？
→ 谁开始付钱？
→ 钱流向哪些环节？
→ 哪个环节的供给最难跟上？
→ 谁拥有控制权和收费权？
→ 收入能否留下利润和现金？
→ 市场是否已经充分定价？
→ 当前价格和风险结构是否允许下注？
```

## 1.3 增长不是利润，稀缺才可能产生利润

[P0·用户原始判断]

> **需求大，不代表股东赚钱。增长不是利润，稀缺才可能产生利润。**

AI 产业研究不能只写 TAM，也不能只写 token、用户数或资本开支。真正要找的是：

- 需求增长是否快于供给扩张；
- 供给为什么难扩，是产能、良率、认证、工程复杂度、客户集成、软件生态还是数据闭环；
- 公司是否控制这个约束，而不是只是经过这个约束；
- 稀缺是否带来价格、合同、毛利率和现金流改善；
- 稀缺可以维持多久，什么时候会被扩产、替代、自研或技术效率反噬。

因此，每个瓶颈判断都必须同时启动一个 **供给反噬时钟**。

## 1.4 政策给风，不替利润背书

[P0·用户原始判断]

政策、宏观流动性和资本开支只能提高研究优先级，不能替企业的业务票背书。

需要区分两套水：

```text
产业需求的水：预算 → 订单 → 出货 → 使用量 → 收入 → 利润 → 现金
金融市场的水：政策 → 信用 → ETF/基金流 → 板块风险偏好 → 标的估值与交易深度
```

前者决定公司是否真正变好，后者决定价格什么时候涨、能涨多快、退出是否顺畅。二者可以互相强化，但不能互相替代。

## 1.5 我赚的到底是什么钱

[P0·用户原始判断]

每个 AI 标的必须明确属于哪一种回报来源：

1. **价值创造的钱**：收入、利润和自由现金流增长。
2. **供需错配的钱**：需求先到、供给来不及，价格和毛利上升。
3. **预期差的钱**：经营数据或产业变化高于市场一致预期。
4. **资金重定价的钱**：ETF、主动基金、政策资金和风险偏好把价格推向新的估值区间。
5. **事件跳变的钱**：订单、财报、产品验证、监管或市场认知发生离散变化。

一个标的可以同时包含几种钱，但不能含糊地写成“AI 长期趋势的钱”。

## 1.6 吃鱼身，而不是证明自己最早或最晚

[P0·用户原始判断]

Murphy 更适合的不是在概念最早期押注所有不确定性，也不是等所有证据都公开后追最后一段，而是：

> **在方向已被验证、证据网络正在形成、利润开始兑现、市场尚未完全定价时，吃主升段的鱼身。**

这意味着：

- 允许错过最早的鱼头；
- 不因为“未来空间大”长期忍受没有证据的等待；
- 达到原有预期或供给开始反噬时，不贪最后的鱼尾；
- 看错可以小亏，不能让一次错误伤害生存。

## 1.7 用事实修正判断，用价格决定下注，用纪律控制错误

[P0·用户原始判断]

价格下跌只可能改善回报票，不会自动提高业务胜率。一次急跌后要先问：

- 下跌来自情绪、流动性、宏观传导、行业周期，还是基本面恶化？
- 长期现金流、竞争优势、资产价值是否改变？
- 新价格是否覆盖等待、脆弱性和退出成本？

每次持有、加仓和重新买入，都是一次新的座位拍卖。成本价没有投票权，过去投入的钱没有投票权。现金和悬置都是合法状态。

# 第二部分：AI 产业的总工作模型

## 2.1 一句话主线

[P0·用户原始判断]

> **AI 进入推理与 Agent 阶段后，真正的投资主线不是“谁发布了更强模型”，而是：真实使用是否持续增长，增长是否制造新的系统瓶颈，瓶颈公司是否拥有控制权和定价权，并最终把需求转化为利润。**

## 2.2 AI 不是一个单一产业，而是一条不断迁移的价值链

[SYNTHESIS·工作模型]

目前可以把 AI 的长期演化压缩为四个阶段：

| 阶段 | 用户购买的东西 | 核心需求 | 主要瓶颈 | 可能的第一现金接收者 |
|---|---|---|---|---|
| Scaling / Training | 更强的通用能力 | 更大训练规模、更快迭代 | GPU、HBM、先进封装、网络、电力 | GPU、存储、封装、网络、电力设备 |
| Inference / Agent | 可持续完成数字任务 | token 吞吐、延迟、成本、上下文、工具调用、稳定性 | 推理算力、KV Cache、存储、网络、Memory、Runtime、Eval、权限 | 推理平台、存储、数据平台、Agent 基础设施 |
| Physical AI | 可执行现实任务 | 感知、规划、控制、安全、端云协同 | 端侧算力、传感器、执行器、电池、热管理、数据、控制系统 | 端侧芯片、核心部件、机器人平台、场景运营商 |
| Real-world Data Loop | 可持续学习和复利的现实能力 | 数据产生→理解→决策→执行→反馈 | 高频场景、数据所有权、闭环速度、部署密度 | 控制数据闭环和场景入口的平台 |

这四个阶段不是严格替代关系，而是叠加关系。训练仍会继续，推理不断放量，Physical AI 会带来新的端侧和云端需求，真实世界数据又会反过来训练模型。

## 2.3 训练决定智能边界，应用决定经济价值

[P0·用户原始判断]

Murphy 仍然相信 Scaling：更大的训练、更好的算法和更多资源仍能带来能力提升。但大模型公司的竞争终局不会只看参数量，而会落到三个变量：

1. **成本**：同样质量的智能服务，谁的单位成本更低；
2. **时间**：谁能更早数月推出可用能力，获得用户和数据；
3. **用户体验**：谁能把模型能力变成稳定、连续、有记忆、能完成任务的产品。

基础模型决定智能的上限，应用和工作流决定智能能否进入业务、产生收入和留下利润。

因此需要长期观察一个关键迁移：

```text
模型能力稀缺
→ 推理能力商品化
→ 公共信息和通用执行贬值
→ 私有数据、长期上下文、分发入口、用户关系、行业工作流和现实闭环升值
```

## 2.4 智能商品化后的稀缺资源

[P0·用户近期思考]

受到“智能商品化、验证者定律、锯齿状边缘”等框架影响，当前形成的工作判断是：

- 当生成和执行成本下降，单纯“能做”会快速贬值；
- AI 能力在不同任务上呈锯齿状分布，不能用一个总分替代具体场景验证；
- 只有拥有可验证结果的任务，才适合快速被 AI 接管；
- Benchmark 和 Eval 的目的不是做排行榜，而是让系统进化发生；
- 真正稀缺的能力会迁移到问题定义、目标函数、验证标准、私有上下文和反馈闭环。

这也是 Murphy 职业和投资判断逐渐汇合的地方：

> **未来更有价值的，不只是执行任务的人，而是能定义问题、组织系统、设计评测、判断结果和控制反馈闭环的人或公司。**

# 第三部分：训练、推理与系统瓶颈

## 3.1 有效 token 吞吐，而不是单一 FLOPS

[P0·本地核心原稿]

```text
有效 token 吞吐
≈ 算力
× HBM 容量
× HBM 带宽
× 网络互联
× 电力与散热
× 存储和数据供应
× 软件调度效率
× 输出质量与可验证性
```

GPU 很重要，但 AI 工厂不是单卡生产函数。任何一个关键环节不足，昂贵 GPU 都可能等待数据、等待内存、等待通信或等待电力。

这是一种近似 Leontief 的互补约束：短板决定系统产出。

## 3.2 为什么推理和 Agent 可能放大需求

[P0·用户原始判断]

一次聊天可能只调用一次模型；一个 Agent 完成一项工作，可能需要：

- 规划和任务拆解；
- 多轮检索和长上下文读取；
- 调用多个工具；
- 反思、重试和验证；
- 读写 Memory；
- 多模型路由；
- 最终结果检查。

因此，Agent 不是把一次问答简单自动化，而是把一次任务变成几十次乃至更多推理调用。即使单位 token 成本下降，总任务量和每任务调用次数仍可能推动总需求上升。

但需求不能只由 token 数证明。真正的“有效需求”必须对应：

- 用户愿意持续使用；
- 企业愿意持续付费；
- 任务完成率和经济收益提高；
- 模型调用能够进入收入或成本节省；
- 不是为了弥补模型不稳定而产生的无效重试。

## 3.3 瓶颈迁移链

[P0/P1 混合，需持续核验]

当前的产业路径可以先写成：

```text
GPU 计算
→ HBM / 先进封装
→ 机内与机间网络
→ 光互联 / 光模块 / 硅光 / CPO
→ 电力 / 变压器 / 液冷 / 并网
→ 存储 / KV Cache / 数据搬运
→ Agent Runtime / Memory / Eval / 权限 / 企业控制平面
→ 端侧算力 / 传感器 / 执行器 / 真实世界数据
```

这不是一条永远成立的固定顺序，而是一张研究地图：每解决一个短板，下一个约束可能暴露，资本开支和利润池随之迁移。

## 3.4 HBM 和存储：从商品周期到 AI 生产资料的假设

[P0·用户原始判断]

HBM 的核心逻辑不是“AI 概念存储”，而是：

```text
模型更大、上下文更长、并发更高、Agent 步数更多、多模态更重
→ KV Cache 和参数搬运增加
→ 内存容量、带宽和能耗成为吞吐约束
→ HBM 单卡价值量和高性能存储需求上升
```

但“从周期品变成结构性瓶颈”仍然是一项假设，必须用以下事实验证：

- HBM 价格和合同期限；
- 产能、良率和客户认证；
- 单卡 HBM 容量与系统架构；
- 推理收入和部署量；
- 云厂商资本开支结构；
- 内存厂毛利率、库存和经营现金流；
- 供给扩张速度是否重新超过需求。

AI Memory 还包括另一层含义：企业 Agent 的长期记忆、向量检索、持久化状态和用户上下文。它既可能增加云端存储需求，也可能通过更好的压缩和状态管理减少重复计算。

## 3.5 网络与光互联：为了提高昂贵算力的利用率

[P0·用户原始判断]

网络价值不来自“数据中心扩张”这一泛化叙事，而来自一个更具体的付款逻辑：

```text
GPU 很贵
→ GPU 等待通信会造成巨大浪费
→ 客户愿意为更高利用率和更低每 token 成本付费
→ 高速交换、SerDes、光模块、硅光和 CPO 获得价值
```

研究 ANET、AVGO、MRVL、CRDO、ALAB、Lumentum、Coherent、Nokia 等公司时，必须回答：

- 它解决的是哪一层通信瓶颈；
- 客户是否已经付费，而不是技术路线可能受益；
- 标准、封装和架构变化是否可能绕过它；
- 收入增长是否能穿透到毛利和现金；
- 当前估值是否已经反映未来若干代产品。

## 3.6 电力、液冷和能源：物理上限，但不是永远的利润权

[P0/P1 混合]

AI 数据中心最终必须把电转化为 token。电网接入、变压器交付、机柜功率密度和散热能力可能成为最硬的物理约束。

但“缺电”不等于所有电力资产都受益。必须继续区分：

- 谁负责新增供电，谁只是拥有存量资产；
- 电价、容量费和合同由谁承担；
- 并网和建设周期是否真的形成收费权；
- 核电、燃气、储能、电网设备、液冷在不同地区的传导路径；
- 效率提升、自研芯片和调度优化是否降低单位任务能耗。

## 3.7 龙二机会：供给紧张中的第二来源

[P0·用户原始判断]

龙二的机会不来自“比龙头便宜”，而来自：

```text
需求强到龙头无法满足
→ 客户必须建立第二来源
→ 第二供应商达到可用线并通过认证
→ 订单快速转化为收入
→ 利润率改善
→ 市场原先预期很低
```

适用范围可能包括晶圆代工、HBM、定制 ASIC、网络和光学器件。但一旦龙头供给恢复、客户自研成熟或第二供应商无法量产，龙二弹性会消失。

# 第四部分：一个需要保留的深层矛盾——总需求增长与单位智能效率

## 4.1 不确定性压缩效率

[P1·AI 推演，尚未由 Murphy 完全确认]

本地材料提出了一个很有解释力的指标：

> **智能的终极度量，不只是 token、算力或参数量，而是每单位能量和成本消除多少任务不确定性。**

它把多个问题统一起来：

| 表面问题 | 深层解释 |
|---|---|
| 回复慢 | 重复或无效计算过多 |
| 回答不准 | 内部模型没有被现实反馈校正 |
| 上下文丢失 | 已消除的不确定性被丢弃，需要重新计算 |
| Agent 调用不稳 | 可靠行动路径没有被压缩和验证 |
| 成本高 | 大量计算没有转化为任务进展 |

由此可以提出一个新的研究变量：

```text
Uncertainty Compression Efficiency
= 每焦耳 / 每美元 / 每 token 所消除的有效任务不确定性
```

## 4.2 “token 暴涨”与“长期能耗下降”并不必然冲突

[SYNTHESIS·工作模型]

当前存在两组看似冲突的判断：

- 推理、Agent、多模态和 Physical AI 会扩大总调用量；
- 持久世界模型、Memory、缓存、路由、端侧计算和专用芯片会降低单位任务计算量。

更合理的三阶段解释是：

1. **安装期**：需求增长远快于效率提升，总算力、电力和硬件投入上升；
2. **扩散期**：单位成本下降带来更多使用，Jevons 效应使总需求仍然扩大；
3. **成熟期**：任务结构稳定、状态可复用、端侧和专用架构成熟，单位智能成本大幅下降，硬件利润占比可能回落。

因此，AI 基础设施可以拥有一个强劲但有期限的窗口，却不一定拥有永久不变的利润份额。

对投资最重要的问题不是“效率会不会提升”，而是：

> **在我的持有窗口内，真实需求增长是否持续快于供给扩张和单位效率提升？**

# 第五部分：AI 应用、企业控制平面与价值捕获

## 5.1 企业 AI 的最短价值链

[P0·用户原始判断]

Murphy 更看好以下特征的 AI 场景：

- 结果可验证；
- 输入输出明确；
- 流程化和高频；
- 能嵌入企业工作流；
- 有权限、审计和责任边界；
- 有持续反馈，可以形成 Memory 和数据闭环；
- 能直接增加收入、降低成本或缩短时间。

典型方向包括：软件工程、代码开发、企业知识库、工作日志和会议消化、销售/CRM/客服、研发文档、经营分析、Agent 工作流编排和企业决策支持。

## 5.2 企业 AI 的控制平面

[SYNTHESIS·工作模型]

当模型逐渐商品化，企业真正需要的不是“再接一个聊天框”，而是一个控制平面：

```text
企业私有数据
+ Ontology / 业务对象
+ 权限和审计
+ 工具和工作流
+ Memory / 状态
+ Eval / 结果验证
+ 部署与版本治理
= 可在真实业务中运行的 Agent 系统
```

这解释了为什么 Palantir、数据平台、云数据库、企业搜索、Observability、Agent Runtime 和知识图谱可能比单一模型调用更容易形成组织粘性。

开源模型不需要在所有能力上打败最强闭源模型。它只需要在大量普通任务上达到“足够好”，再由工作流、上下文准备、工具调用和检查系统弥补差距，从而提供成本、数据主权和供应商选择权。

## 5.3 公共信息贬值，私有上下文升值

[P0·用户近期判断]

当人人都能获得类似的模型能力和公开信息时，纯信息差的价值下降。新的差异可能来自：

- 企业独有的数据；
- 用户长期 Memory；
- 真实交易和行为历史；
- 业务流程和责任边界；
- 高质量 Eval；
- 低成本部署与反馈；
- 分发入口和用户关系。

这既是 AI 产品方向，也是投资判断：谁控制了这些资产，谁更有可能把智能商品化后的价值留下来。

## 5.4 Agentic Commerce：互联网入口、广告和支付的重新分配

[P1·外部研究线索，尚未完全内化]

Agent 替用户搜索、比较、决策和付款，可能改变：

- 谷歌和 Meta 的广告入口；
- 亚马逊等平台的 cross-sell 和广告收入；
- 商家对流量平台的依赖；
- 长尾商家的获客机会；
- PayPal 等快捷支付中间层；
- 稳定币和机器支付的需求。

当前不能直接得出某家公司的投资结论。需要验证 Agent 是否真的拥有登录、身份、支付、责任和商家接受度，以及平台如何收费。

# 第六部分：Physical AI、机器人与真实世界数据闭环

## 6.1 机器人是 AI 的下半场，是当前个人强判断而非行业事实

[P0·用户近期判断]

Murphy 当前看好机器人，并提出一个带有强主观色彩的比例假设：

> **大模型和算力基建可能只占 AI 长期价值的一部分，机器人和 Physical AI 可能占更大的 80%。**

这不应写成预测数字，而应保存为研究方向：AI 的最终生产率价值不只在信息世界，而在现实世界的搬运、制造、驾驶、巡检、照护、修理和建造。

大模型解决“帮我想、帮我说、帮我处理信息”；机器人解决“帮我搬、帮我做、帮我操作现实世界”。

机器人真正出售的是：

> **现实世界劳动的可购买化、可复制化和可资本化。**

## 6.2 Chat AI → Agentic AI → Physical AI

[P0/P1 已被吸收的工作模型]

- Chat AI：生成内容和答案；
- Agentic AI：在数字系统中规划和执行任务；
- Physical AI：通过机器人、汽车、无人机和工业设备改变物理世界。

Physical AI 不会是纯云端，也不会是纯端侧，而是 cloud-edge 协同：

| 层级 | 主要职责 |
|---|---|
| 云端 foundation model | 通用认知、长程规划、知识调用、跨设备学习、训练更新 |
| 本地 VLM/VLA | 理解当前场景，把高层意图转换为动作计划 |
| 本地传统算法和小模型 | SLAM、状态估计、避障、轨迹、抓取、力控、安全监控 |
| 实时控制器 | 电机、关节、动力学约束、急停和确定性控制 |

云端让机器人更聪明，本地算力决定机器人能否实时、安全、可靠地工作。

## 6.3 Physical AI 的核心约束

[P0·已吸收判断]

1. **实时性**：物理闭环不能等待不稳定的云端响应；
2. **安全性**：错误会造成现实损坏，必须有本地冗余和 fallback；
3. **网络可靠性**：工厂、仓库、道路、农田和家庭不能假设永远联网；
4. **隐私与带宽**：视频、空间、人的行为和工业数据不适合全部上传；
5. **能耗和散热**：机器人还要驱动电机，performance per watt 比峰值算力更重要；
6. **数据稀缺**：高质量动作数据远少于互联网文本和图片；
7. **Embodiment Gap**：同一任务在不同本体上的动作空间不同；
8. **Sim-to-real**：现实中的摩擦、材料、遮挡、噪声和执行误差难以完全仿真；
9. **工程可靠性**：从 Research 到 Engineering 的距离仍然很大。

## 6.4 英伟达和高通代表两条端侧路径

[P0/P1 已吸收判断]

- **NVIDIA**：从数据中心训练和推理向 Jetson、DRIVE、Isaac 和机器人/汽车全栈延伸，优势是 GPU、CUDA、仿真、统一软件生态和高端算力。
- **Qualcomm**：从移动 SoC、连接和低功耗异构计算向机器人、汽车和 IoT 延伸，优势是 NPU、CPU、ISP、DSP、无线连接和规模化端侧经验。

高端复杂本体可能更需要强 GPU 平台，大量成本和功耗敏感的 Physical AI 设备可能更适合低功耗 NPU。判断不能只比较 TOPS，而要比较：性能/瓦、总成本、开发生态、安全、连接和量产能力。

## 6.5 AI 硬件的终局不是数据采集器，而是 Data Hub

[P0·用户近期判断]

硬件如果只采集数据、提供一个功能，很容易被替代。真正有价值的 AI 硬件需要逐步成为 Data Hub：

- 持续感知用户和环境；
- 连接多个场景的数据；
- 建立长期 Memory；
- 理解用户状态和意图；
- 参与决策和执行；
- 接收现实反馈并持续更新。

因此投资时，不只问“谁拥有最多数据”，而要问：

```text
谁控制数据产生
→ 谁能理解数据
→ 谁能据此决策
→ 谁能执行动作
→ 谁能得到反馈
→ 谁能让闭环越来越快、越来越真实、越来越难复制
```

真实世界数据闭环可能是 AI 下一阶段最重要的资产之一。

## 6.6 当前不应忽视的反证

[OPEN·待验证]

机器人行业仍可能比市场想象得慢：

- manipulation 尚未达到通用可靠；
- 硬件形态和软件路线没有完全收敛；
- 数据极度稀缺，早期改善不能线性外推；
- 量产、维护、安全责任和场景 ROI 未被普遍证明；
- 机器人可能先在工业、物流和特定任务落地，而非快速进入家庭；
- 产业价值很大不等于当前上市公司可以留下利润。

所以“机器人是长期最大方向”只能提高研究优先级，不能降低公司级证据标准。

# 第七部分：AI 资本开支、硬件利润池与泡沫检验

## 7.1 需要检验的不是“AI 是否重要”

[P0·用户原话]

> **本模型不否定 AI 的生产率价值，也不预测 AI 失败；它只检验一个更窄的问题：在需求分层和价格竞争后，基础模型 ARR 是否足以支撑硬件利润在美国上市公司利润池中长期维持当前异常高的份额。**

这是当前 AI 投资研究最重要的约束之一。

## 7.2 硬件利润高企的来源

[SYNTHESIS·工作模型]

当前硬件利润可能来自多种叠加：

- 模型公司和云厂商军备竞赛；
- 训练和推理需求提前建设；
- GPU、HBM、封装、网络、电力等多环节供给约束；
- 长约、预付款、订单积压和交付周期；
- 应用收入曲线落后于基础设施投入曲线的时间错配；
- 市场愿意为稀缺供给和未来增长支付高估值。

这说明高利润可以持续一段时间，但不证明永久持续。

## 7.3 硬件利润池的八个验收变量

后续应建立持续更新的仪表盘：

1. **基础模型与 AI 应用 ARR**：收入总额、增速、付费率和客户留存；
2. **绝对毛利和经营利润**：不能只看毛利率，AI 合同金额和推理成本必须同时看；
3. **Hyperscaler ROIC**：AI 资本开支是否带来云收入、广告效率、企业软件收入或成本节省；
4. **资本开支与折旧**：建设承诺、折旧周期、融资成本和自由现金流；
5. **供给扩张**：GPU、HBM、CoWoS、网络、电力和机房何时从短缺转向充足；
6. **效率提升**：量化、蒸馏、MoE、缓存、Memory、自研 ASIC、路由和端侧计算；
7. **竞争与议价**：NVIDIA、AMD、TPU、定制 ASIC、云厂商和 NeoCloud 的价格与利润分配；
8. **应用层价值创造**：AI 是否进入客服、编程、金融、物流、制造、科研和自动驾驶，并真实提高收入或利润。

## 7.4 AI Infra 与 AI Application 的相对收益是一个时点问题

[P0/P1 混合]

近期外部研究提出“市场开始奖励有 AI 收入的公司、惩罚只有资本开支的公司”，并判断应用可能开始跑赢基础设施。

Murphy 的更合适表述应是：

- 基础设施需求短期仍可能增长；
- 但市场对“只投入、不变现”的容忍度会下降；
- 资本开支不再自动带来估值上升，必须证明 ROIC；
- 应用收入、企业提效和传统行业利润改善的权重会提高；
- Infra 与 Application 的相对表现取决于预期和价格，而不只是产业阶段。

## 7.5 泡沫破裂可能反而加速真实应用

[P0·用户近期判断]

AI 估值或股票下跌不一定意味着 AI 产业失败。泡沫收缩可能降低：

- GPU 租赁价格；
- 推理和云资源成本；
- 机器人 BOM；
- 人才薪酬和融资成本；
- 低质量项目对资源的争夺。

这可能使真正有 ROI 的应用、企业流程和机器人场景更快成立。

因此投资需要区分：

```text
产业长期生产率价值
≠ 当前公司盈利能力
≠ 当前股票价格合理性
≠ 当前持有工具和期限的安全性
```

> [!warning]
> 本节只保存稳定的实体模型，不保存当前价格、仓位和买卖建议。ORCL、NBIS 等活跃预期必须留在 `03_STATE`。

## 8.1 NVIDIA

当前工作模型：NVIDIA 不是单一 GPU 公司，而是从训练、推理、网络、CPU、仿真到边缘平台的 AI 工厂体系。

长期观察变量：

- 推理是否成为更持续的收入核心；
- Blackwell / Rubin 是否持续提高系统价值量；
- Networking、CPU、软件和边缘计算的占比；
- CUDA 和整套开发生态是否继续形成控制权；
- 自研 ASIC、TPU、AMD 和客户议价是否侵蚀利润；
- AI 应用收入能否支撑整个资本开支链；

## 8.2 Google

当前工作模型：Google 拥有模型、TPU、云、搜索、YouTube、Workspace、Android 等纵向整合优势，可以用成本、捆绑和分发竞争。

核心矛盾：AI 增强其产品和云竞争力，也可能侵蚀搜索广告入口。不能因为 Gemini 或 TPU 变强，就认为搜索经济的威胁已经消失。

## 8.3 OpenAI 与 Anthropic

当前工作模型：基础模型公司具有高增长和高资本强度的双重属性。训练成本、推理成本和下一代模型投入可能形成负向现金流滚雪球；现金流改善取决于收入回报率提升或训练投入增速下降。

需要验证：

- 消费、企业、API、Agent 和新产品收入结构；
- 用户留存、付费率和企业嵌入深度；
- 推理毛利和训练资本化/折旧；
- 企业超级入口是否成立；
- 谷歌、开源模型和价格战；
- 基础模型 ARR 是否最终覆盖硬件利润池。

## 8.4 Oracle

当前稳定模型：Oracle 的价值不只在出租 GPU，而在企业数据库、存储、安全和既有数据关系形成的附加收入与数据引力。

核心风险：

- 云容量建设和融资；
- 大客户集中；
- 为抢项目接受较低利润；
- 竞争从三朵云扩展到 Oracle、NeoCloud 和模型公司自建云；
- GPU 租赁同质化后，附加服务能否维持利润。

## 8.5 Nebius

当前稳定模型：Nebius 是 AI 云利用率和建设风险的研究样本。其价值来自提前获得算力、客户和资本支持，风险来自供给投产、利用率、融资和竞争。

Murphy 当前更偏向半年到一年窗口研究：当供给快速投产、租赁竞争和价格下降时，原有稀缺逻辑可能改变。因此 NBIS 的具体预期必须保留在 `03_STATE`，不能写死进长期领域知识。

## 8.6 Palantir

当前工作模型：Palantir 更接近企业 AI 控制平面，而非普通模型公司。Ontology、Foundry、AIP、Apollo、权限、审计和部署可能把模型嵌入真实决策。

需要验证：平台的高收费是否来自不可替代控制权，还是重服务和客户集中；开源模型普及是否强化其控制平面价值。

## 8.7 存储产业链与 501096

存储是领域知识，501096 是投资工具，两者不能混写。

- 领域知识保存 NAND、DRAM、HBM、企业级 SSD、控制器、Memory 和持久化需求；
- 基金持仓、经理风格、折溢价、仓位和退出条件进入 `03_STATE` 或组合系统；
- ETF/LOF 只适合表达行业 beta，不能自动代表某一条纯粹的存储 thesis。

# 第九部分：从产业认知到可下注研究

## 9.1 六个瓶颈测试

[P0·用户原始框架]

任何 AI 公司进入核心研究池前，必须回答：

1. **Need**：没有它，系统是否明显跑不动，客户是否真的愿意付钱？
2. **Constraint**：它限制吞吐、延迟、成本、稳定性、安全还是只是边缘优化？
3. **Control**：公司是否控制关键环节，还是可替代的小供应商？
4. **Pricing**：需求增长能否改善价格、合同条款或毛利？
5. **Capture**：收入能否留下经营利润和现金，而不是被客户、竞争或资本开支拿走？
6. **Duration**：约束是一年景气、三年窗口，还是长期平台能力？

## 9.2 四票模型

研究结论不能只写“看好/看空”，而应拆成：

- **H_B｜Business**：业务、行业和利润路径是否成立；
- **H_R｜Return**：当前价格是否提供足够预期回报；
- **H_L｜Path/Liquidity**：等待路径、融资、波动和退出是否可承受；
- **H_C｜Capital**：组合、风险簇和最大损失是否允许占座。

价格下跌主要更新 H_R，不直接更新 H_B。政策和资金通常先更新 H_R/H_L，只有传导到订单、利润和现金时才更新 H_B。

## 9.3 泊松过程：买的是状态跳变强度

[P0/P1 已被吸收的投资纪律]

投资的大部分时间没有重要事件。收益往往集中在少数订单、财报、价格反转、管理层上调指引或市场重新认识的窗口。

需要估计的不是“明天涨不涨”，而是：

```text
state_jump_intensity = λ
valid_jump_probability = P(真状态迁移 | 事件发生)
payoff_asymmetry = 上行赔率 / 下行损失
seat_legality = 当前价格与资本结构是否允许下注
```

单位时间可投资价值可以近似写成：

```text
Investable EV per unit time
≈ λ × P(valid state jump | event) × Payoff
− Carry Cost
− Fragility Cost
− Opportunity Cost
− False Positive Cost
```

高质量等待必须同时满足：

- λ 在上升；
- 证据网络在变密；
- 有明确 falsifier；
- 有 review clock；
- 仓位与等待风险匹配。

“已经等了很久”没有投资价值。指数等待的无记忆性提醒我们：沉寂很久、跌很久、估值压很久，都不代表马上轮到它。

## 9.4 贝叶斯更新和证据网络

一条新闻不能改变 thesis。有效证据网络需要多个相对独立的信号互相确认：

```text
真实使用/客户采用
+ 收入和订单加速
+ 毛利与现金不恶化
+ 供给约束存在
+ 行业趋势配合
+ 市场尚未完全定价
```

更新时必须记录：

- 新证据更新哪一票；
- 证据是 leading、coincident 还是 lagging；
- 是否与其他来源独立；
- 原判断从什么状态变到什么状态；
- 哪个反证会让后验下降；
- 下一次复查时间。

## 9.5 ETF 与个股的不同研究深度

[P0·用户明确约束]

- ETF/基金主要表达行业、政策、资金流和板块 beta；
- 个股必须研究控制权、利润留存、资本结构和公司级预期差；
- 只理解行业时优先 ETF，不假装拥有公司 alpha；
- ETF 仍需审计指数、持仓、经理风格、折溢价、流动性和风险簇。

## 9.6 一年兑现原则

Murphy 绝大多数标的按约一年窗口理解，约 90% 是周期轮动或阶段性变化，而非永久持有。

因此每个 AI thesis 都要写：

- 未来一年最可能发生的 1—3 个状态跳变；
- 哪个财务或产业指标负责验收；
- 供给何时投产；
- 市场预期何时可能追上；
- 达到什么条件离场；
- 什么情况说明窗口已经关闭。

# 第十部分：当前核心矛盾与开放问题

## 10.1 基础模型 ARR 能否支撑硬件利润池

**当前状态：OPEN。**

需要建立收入、毛利、资本开支、折旧、供给和应用 ROI 的统一模型。不能只拿 OpenAI/Anthropic 收入与整个 AI 基建支出做静态比较，也不能把传统企业的成本节省完全忽略。

## 10.2 总 token 需求能否持续快于效率提升

**当前状态：中期偏是，长期未知。**

Agent、多模态和 Physical AI 增加调用；Memory、缓存、路由、专用芯片和端侧推理降低单位任务成本。关键是不同时间尺度上的净效应。

## 10.3 基础模型会不会商品化，利润迁移到应用

**当前状态：方向上认可，速度未知。**

模型能力可能集中在少数前沿公司，但大量普通任务可以被便宜模型和开源模型满足。应用、分发、数据、工作流和控制平面可能拿走更多经济价值。

## 10.4 AI Infra 何时从稀缺变成供给过剩

**当前状态：需要按环节分别判断。**

GPU、HBM、光学、电力、机房和云租赁不会同时反转。必须逐层跟踪订单、交付、价格、库存、利用率和融资。

## 10.5 机器人长期价值很大，为什么当前难下注

**当前状态：长期高优先级，当前低确定性。**

Manipulation、数据、硬件形态、可靠性、场景 ROI 和量产均未充分收敛。更适合跟踪已进入供应链、能量产、有真实订单的零部件、端侧平台和高 ROI 场景。

## 10.6 谁控制真实世界数据闭环

**当前状态：核心新主线。**

需要判断机器人本体、操作系统、场景运营商、传感器平台、云模型或数据平台，谁能真正控制数据的产生、使用、反馈和跨设备学习。

## 10.7 AI 泡沫收缩是风险还是生产率加速器

**当前状态：两者都是。**

对高估值资产是风险，对真实应用可能是成本红利。需要区分产业成本下降和股东回报下降。

## 10.8 Benchmark 和 Eval 如何转化为商业护城河

**当前状态：职业和投资共同研究方向。**

Eval 如果只做一次测评不构成护城河；如果嵌入开发、部署、反馈和责任闭环，可能成为企业 AI 的控制权和切换成本。

# 第十四部分：极简压缩版

> **投资之道：变化 → 稀缺 → 控制权 → 利润 → 预期差 → 价格与纪律。**
>
> **AI 产业：训练扩展智能边界，推理和 Agent 扩大使用，Physical AI 把智能带入现实，真实世界数据闭环决定长期复利。**
>
> **AI 投资：不问“是不是 AI 公司”，而问真实需求是否增长、哪个瓶颈被放大、谁控制瓶颈、能否定价、利润能否留下、供给何时反噬、当前价格是否仍有一年兑现的赔率。**
